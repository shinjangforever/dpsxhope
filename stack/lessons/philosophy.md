# บทเรียนสาย ปรัชญา

คำถามของสายนี้: เรารู้ได้อย่างไรว่าใช้ได้ และใครรับผิดชอบ

ทำตามลำดับจากระดับ 1 แต่ละระดับมีขั้นที่ต้องทำ สิ่งที่ควรเห็น และเกณฑ์ว่าผ่าน รันคำสั่งทั้งหมดจาก root ของ repo ภาพรวมของสายอยู่ที่ [PATHS.md](../PATHS.md) และคำอธิบายเครื่องมืออยู่ที่ [TOOLS.md](../TOOLS.md)

ดูใน terminal: `python hope.py stack learn philosophy`

## ระดับ 1 เริ่มใช้

ใช้ของที่มีให้ได้ผล โดยยังไม่ต้องเขียนโค้ด เมื่อจบระดับนี้: ไม่เชื่อคำตอบของ AI โดยไม่ตรวจ และรู้ว่าตรวจกับอะไร

1. ถามคำถามที่คำตอบไม่มีในเอกสารของคุณ

   ```bash
   python hope.py ask "คำถามที่เอกสารไม่ได้ตอบ"
   ```

   ควรเห็น: ดูว่าโมเดลบอกว่าไม่พบ หรือแต่งคำตอบขึ้นมา
2. สำหรับคำตอบหนึ่งข้อที่ได้ เปิดแหล่งอ้างอิงแล้วหาประโยคที่รองรับ ถ้าหาไม่เจอ ให้ถือว่าคำตอบนั้นยังไม่มีหลักฐาน
3. ดูว่าคู่มือนี้แยกสิ่งที่ทดสอบแล้วกับยังไม่ได้ทดสอบอย่างไร

   ```bash
   python hope.py list -v
   ```

   ควรเห็น: แต่ละต้นแบบมีรายการ "ทดสอบแล้ว" และ "ยังไม่ได้ทดสอบ"
4. เขียนสองรายการแบบเดียวกันสำหรับงานของคุณเองหนึ่งชิ้น

**ผ่านระดับนี้เมื่อ:** ไม่ใช้คำตอบของ AI โดยไม่เปิดแหล่งอ้างอิง และแยกได้ว่าอะไรในงานของคุณพิสูจน์แล้ว อะไรแค่เชื่อ

## ระดับ 2 ปรับใช้

แก้ค่า เขียนส่วนเล็ก และต่อยอดต้นแบบให้เข้ากับงานของตัวเอง เมื่อจบระดับนี้: แยกได้ว่าข้อความไหนเป็นหลักฐาน ข้อความไหนเป็นแค่ข้ออ้าง

เครื่องมือที่เริ่มใช้: audit log, llm-eval, การขออนุมัติ tool

1. อ่านกติกาของคู่มือเรื่องแหล่งอ้างอิงและวันที่ตรวจ
   ดู: CONTRIBUTING.md
2. เลือกข้ออ้างหนึ่งข้อจากคำตอบของ AI แล้วเขียนเป็นรูป: หลักฐาน → ข้อสรุป ถ้าข้อสรุปไม่ตามมาจากหลักฐาน ให้เขียนว่าขาดอะไร
3. หาตัวอย่างเหตุผลวิบัติสามแบบในคำตอบของ AI หรือในข้อความโฆษณา: อ้างคนดัง, สรุปจากตัวอย่างเดียว, เกิดก่อนจึงเป็นเหตุ
4. ดูว่าระบบถือข้อความในเอกสารเป็นข้อมูล ไม่ใช่คำสั่งอย่างไร
   ดู: ช่อง system ของขั้น summary ใน agent-kit/jobs/inbox-summary.json

**ผ่านระดับนี้เมื่อ:** แยกได้ว่าประโยคไหนเป็นหลักฐาน ประโยคไหนเป็นข้อสรุป และบอกได้ว่าข้อสรุปตามมาจากหลักฐานจริงไหม

## ระดับ 3 สร้างระบบ

ทำให้คนอื่นใช้ได้ รันได้ต่อเนื่อง และดูแลต่อได้ เมื่อจบระดับนี้: ออกแบบจุดที่คนต้องตัดสินใจ และบันทึกการตัดสินใจนั้น

1. อ่านบทเรียนของสะพานหุ่นยนต์: ทำไมความมั่นใจที่โมเดลรายงานเองใช้เป็นด่านเดียวไม่ได้
   ดู: fields/robotics/01-heart-to-mechanism.md
2. ดูว่าใครเป็นผู้อนุมัติในระบบนี้: คนกดยอมทีละครั้ง หรือเจ้าของงานใส่ชื่อใน allow_tools ล่วงหน้า
   ดู: agent-kit/README.md หัวข้อ กติกาความปลอดภัย
3. สำหรับระบบของคุณ เขียนตาราง: การกระทำ → ใครอนุมัติ → บันทึกไว้ที่ไหน → ใครรับผิดชอบถ้าผิด
4. หาการกระทำหนึ่งอย่างในตารางที่ไม่มีคนอนุมัติ แล้วตัดสินว่ายอมรับได้ไหม เพราะอะไร

**ผ่านระดับนี้เมื่อ:** ทุกการกระทำที่มีผลจริงในระบบของคุณมีชื่อคนอนุมัติและที่บันทึก หรือมีเหตุผลที่เขียนไว้ว่าทำไมไม่ต้องมี

## ระดับ 4 เชี่ยวชาญ

ออกแบบ วัดผล และตัดสินใจเชิงระบบด้วยหลักฐาน เมื่อจบระดับนี้: ตัดสินได้ว่าระบบไหนควรสร้าง ไม่ใช่แค่สร้างได้หรือไม่

1. อ่านเป้าหมายของคู่มือและชั้น Thinker OS ที่ยังไม่ได้ทำ
   ดู: ROADMAP.md
2. เลือกระบบ AI หนึ่งอย่างที่คุณอยากสร้าง แล้วเขียนว่าใครได้ประโยชน์ ใครเสียประโยชน์ และใครไม่มีสิทธิ์เลือก
3. เขียนว่าถ้าระบบนี้ทำงานได้ดีมาก จะเกิดอะไรกับคนที่ทำงานนั้นอยู่ตอนนี้ ในหนึ่งปีและห้าปี
4. ตอบคำถาม: โมเดลที่สรุปเอกสารได้ถูก "เข้าใจ" เอกสารไหม และคำตอบของคุณเปลี่ยนวิธีที่คุณตรวจผลของมันอย่างไร

**ผ่านระดับนี้เมื่อ:** มีข้อเขียนหนึ่งหน้าที่ตัดสินว่าระบบนี้ควรสร้างหรือไม่ โดยแยกเหตุผลจากความอยากสร้าง (คู่มือนี้ยังไม่มีบทเรียนปรัชญา ขั้นเหล่านี้เป็นแบบฝึกคิด)

คำสั่งที่ไม่ต้องใช้โมเดลหรืออินเทอร์เน็ตถูกรันโดยชุดทดสอบของคู่มือทุกครั้งที่มีการแก้ ส่วนขั้นที่ต้องใช้โมเดล ไฟล์ของคุณ หรือการตัดสินใจของคุณ ต้องทำและตรวจด้วยตัวเอง
