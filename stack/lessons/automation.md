# บทเรียนสาย งานอัตโนมัติ

คำถามของสายนี้: งานนี้เริ่มเองได้ไหม โดยไม่ต้องมีคนสั่งทุกครั้ง

ทำตามลำดับจากระดับ 1 แต่ละระดับมีขั้นที่ต้องทำ สิ่งที่ควรเห็น และเกณฑ์ว่าผ่าน รันคำสั่งทั้งหมดจาก root ของ repo ภาพรวมของสายอยู่ที่ [PATHS.md](../PATHS.md) และคำอธิบายเครื่องมืออยู่ที่ [TOOLS.md](../TOOLS.md)

ดูใน terminal: `python hope.py stack learn automation`

## ระดับ 1 เริ่มใช้

ใช้ของที่มีให้ได้ผล โดยยังไม่ต้องเขียนโค้ด เมื่อจบระดับนี้: รันงานตัวอย่างกับไฟล์ของตัวเอง และรู้ว่าผลอยู่ที่ไหน

เครื่องมือที่เริ่มใช้: Git, hope.py, JSON และ YAML, Ollama, Python, งานอัตโนมัติ (automate.py)

1. ดูงานตัวอย่างที่มี

   ```bash
   python hope.py auto list
   ```

   ควรเห็น: inbox-todo (ไม่ใช้ AI) และ inbox-summary (ใช้ AI)
2. ตรวจไฟล์งาน และดูว่าต้องวางไฟล์ที่ไหน

   ```bash
   python hope.py auto check inbox-todo
   ```

   ควรเห็น: บรรทัด "วางไฟล์ที่:" บอกโฟลเดอร์ inbox
3. วางไฟล์ .txt ที่มีบรรทัดขึ้นต้นด้วย TODO หรือมีคำว่า ต้องทำ ลงในโฟลเดอร์นั้น
4. ดูก่อนว่าจะทำอะไร โดยยังไม่ทำจริง

   ```bash
   python hope.py auto run inbox-todo --dry-run
   ```

   ควรเห็น: รายการขั้นที่จะทำกับไฟล์ของคุณ และข้อความว่ายังไม่ได้ทำจริง
5. ทำจริงหนึ่งรอบ

   ```bash
   python hope.py auto run inbox-todo
   ```

   ควรเห็น: ไฟล์ผลในโฟลเดอร์ outbox และไฟล์ต้นฉบับย้ายไปโฟลเดอร์ done

**ผ่านระดับนี้เมื่อ:** รันงานกับไฟล์ของตัวเองได้ผลถูก และรู้ว่ารันซ้ำแล้วไฟล์เดิมจะไม่ถูกทำอีก

## ระดับ 2 ปรับใช้

แก้ค่า เขียนส่วนเล็ก และต่อยอดต้นแบบให้เข้ากับงานของตัวเอง เมื่อจบระดับนี้: สร้างงานของตัวเองที่รันซ้ำได้โดยผลไม่เพี้ยน

เครื่องมือที่เริ่มใช้: audit log, Bash, JavaScript, n8n, SQLite, Task Scheduler และ cron, unittest, workflow runner

1. คัดลอก agent-kit/jobs/inbox-todo.json เป็นชื่อใหม่ แล้วแก้ keywords ให้เป็นคำของงานคุณ
2. แก้ขั้น write ให้ชื่อไฟล์และเนื้อหาใช้ตัวแปร เช่น ${file_stem} ${date} และผลของขั้นก่อนหน้า ${todo.found}
3. ตรวจไฟล์งาน: ลองพิมพ์ชื่อตัวแปรผิดหนึ่งตัวก่อน เพื่อดูว่าตัวตรวจบอกอะไร

   ```bash
   python hope.py auto check ชื่องานของคุณ
   ```

   ควรเห็น: ข้อความบอกทุกจุดที่ผิด รวมตัวแปรที่ยังไม่มี
4. ลองงานที่มีขั้นถาม AI แบบดูก่อนทำ

   ```bash
   python hope.py auto run inbox-summary --dry-run
   ```

   ควรเห็น: ขั้น summary บอกว่าจะถามโมเดลตัวไหนด้วยข้อความกี่ตัวอักษร
5. ดูคำสั่งตั้งเวลาของระบบปฏิบัติการ (โปรแกรมแสดงคำสั่งให้ ไม่ได้ตั้งให้)

   ```bash
   python hope.py auto schedule inbox-todo --every-minutes 15
   ```

   ควรเห็น: คำสั่งตั้งเวลา ตรวจ และยกเลิก

**ผ่านระดับนี้เมื่อ:** มีไฟล์งานของคุณเองที่ผ่าน auto check และรันสองรอบติดกันแล้วผลไม่ซ้อน

## ระดับ 3 สร้างระบบ

ทำให้คนอื่นใช้ได้ รันได้ต่อเนื่อง และดูแลต่อได้ เมื่อจบระดับนี้: ปล่อยงานให้รันเองได้โดยรู้เมื่อมันพัง

เครื่องมือที่เริ่มใช้: Docker, GitHub Actions

1. ทำให้งานล้มโดยตั้งใจ: สร้างไฟล์ผลชื่อเดียวกันไว้ใน outbox ก่อน แล้วรันงาน
   ดู: ขั้น save ล้มพร้อมเหตุผล ไฟล์ต้นฉบับยังอยู่ใน inbox และรหัสออกเป็น 1
2. อ่านสรุปจาก log

   ```bash
   python hope.py auto report inbox-todo
   ```

   ควรเห็น: จำนวนที่สำเร็จและล้ม เวลาเฉลี่ยต่อขั้น และข้อผิดพลาดที่พบบ่อย
3. ให้งานรันต่อเนื่อง แล้ววางไฟล์เพิ่มระหว่างที่รัน

   ```bash
   python hope.py auto loop inbox-todo
   ```

   ควรเห็น: ทุกรอบบอกเวลาและจำนวนรายการใหม่ กด Ctrl+C เพื่อหยุด
4. เปิดอีกหน้าต่างแล้วรันคำสั่งเดียวกันซ้อน
   ดู: ข้อความว่างานนี้กำลังรันอยู่ในอีกหน้าต่างหนึ่ง
5. อ่านชุดทดสอบว่าสัญญาอะไรไว้บ้าง
   ดู: ชื่อฟังก์ชันใน tests/test_automation.py เช่น test_failed_file_retries_then_stops

**ผ่านระดับนี้เมื่อ:** ตอบได้สี่ข้อของงานคุณ: ดูก่อนทำได้ไหม ทำซ้ำแล้วผลซ้อนไหม ล้มแล้วรู้ได้จากอะไร และหยุดอย่างไร

## ระดับ 4 เชี่ยวชาญ

ออกแบบ วัดผล และตัดสินใจเชิงระบบด้วยหลักฐาน เมื่อจบระดับนี้: ตัดสินด้วยตัวเลขว่างานอัตโนมัติคุ้มที่จะดูแลต่อไหม และรู้ว่าเมื่อไรงานเกินขอบเขตของเครื่องมือนี้

1. จับเวลาที่คุณทำงานนี้ด้วยมือหนึ่งรายการ แล้วให้รายงานเทียบกับเวลาของเครื่อง

   ```bash
   python hope.py auto report inbox-todo --minutes-by-hand 3
   ```

   ควรเห็น: เวลาที่ประมาณว่าใช้ถ้าทำมือ เทียบกับเวลาที่เครื่องใช้ พร้อมหมายเหตุว่ายังไม่รวมเวลาตรวจผลและเวลาดูแล
2. บันทึก log เป็นฐานข้อมูล SQLite แล้วถามต่อด้วย SQL ของคุณเอง

   ```bash
   python hope.py auto report inbox-todo --db auto-log.db
   ```

   ควรเห็น: ไฟล์ auto-log.db มีตาราง steps ถามได้เช่น SELECT step, AVG(ms) FROM steps GROUP BY step
3. เปิดช่องรับไฟล์ทาง HTTP เพื่อให้โปรแกรมอื่น เช่น n8n ส่งงานเข้ามา (ต้องตั้ง AUTO_WEBHOOK_TOKEN ก่อน)

   ```bash
   python hope.py auto serve inbox-todo
   ```

   ควรเห็น: ที่อยู่ http://127.0.0.1:8765/inbox รับเฉพาะจากเครื่องนี้ และต้องมี token
4. อ่านแถว T6 และ T12 ใน threat model ว่าช่องรับไฟล์และการรันค้างกลางขั้นยังมีช่องว่างอะไร
   ดู: stack/THREAT-MODEL.md
5. เขียนว่างานของคุณต้องการคิวงานหรือการกู้กลางขั้นหรือไม่ ถ้าต้องการ งานนั้นเกินขอบเขตของ automate.py

**ผ่านระดับนี้เมื่อ:** มีตัวเลขว่างานอัตโนมัติของคุณประหยัดเวลาได้เท่าไรหลังหักเวลาตรวจผล และตัดสินได้ว่าคุ้มที่จะดูแลต่อไหม

คำสั่งที่ไม่ต้องใช้โมเดลหรืออินเทอร์เน็ตถูกรันโดยชุดทดสอบของคู่มือทุกครั้งที่มีการแก้ ส่วนขั้นที่ต้องใช้โมเดล ไฟล์ของคุณ หรือการตัดสินใจของคุณ ต้องทำและตรวจด้วยตัวเอง
