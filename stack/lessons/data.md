# บทเรียนสาย ข้อมูลและการค้นหา

คำถามของสายนี้: คำตอบมาจากข้อมูลไหน และดีแค่ไหน

ทำตามลำดับจากระดับ 1 แต่ละระดับมีขั้นที่ต้องทำ สิ่งที่ควรเห็น และเกณฑ์ว่าผ่าน รันคำสั่งทั้งหมดจาก root ของ repo ภาพรวมของสายอยู่ที่ [PATHS.md](../PATHS.md) และคำอธิบายเครื่องมืออยู่ที่ [TOOLS.md](../TOOLS.md)

ดูใน terminal: `python hope.py stack learn data`

## ระดับ 1 เริ่มใช้

ใช้ของที่มีให้ได้ผล โดยยังไม่ต้องเขียนโค้ด เมื่อจบระดับนี้: ใส่เอกสารของตัวเอง ถามคำถาม และตรวจคำตอบกับแหล่งอ้างอิง

เครื่องมือที่เริ่มใช้: Claude API, hope.py, Ollama, pypdf, Python

1. ลองเดโมด้วยเอกสารตัวอย่าง

   ```bash
   python hope.py demo
   ```

   ควรเห็น: ช่วงเอกสารที่ค้นเจอสำหรับคำถามตัวอย่าง พร้อมชื่อไฟล์ต้นทาง
2. วางเอกสารของคุณ (.txt .md .pdf) ในโฟลเดอร์ my-docs แล้วสร้างดัชนี

   ```bash
   python hope.py docs
   ```

   ควรเห็น: จำนวนไฟล์และจำนวนช่วงเอกสารที่ทำดัชนี
3. ถามคำถามที่คุณรู้คำตอบอยู่แล้ว

   ```bash
   python hope.py ask "คำถามของคุณ"
   ```

   ควรเห็น: คำตอบพร้อมรายการแหล่งอ้างอิง
4. เปิดไฟล์ต้นทางที่ถูกอ้าง แล้วหาประโยคที่รองรับคำตอบ

**ผ่านระดับนี้เมื่อ:** ถามจากเอกสารของตัวเองได้ และสำหรับทุกคำตอบชี้ได้ว่ามาจากไฟล์ไหน ช่วงไหน

## ระดับ 2 ปรับใช้

แก้ค่า เขียนส่วนเล็ก และต่อยอดต้นแบบให้เข้ากับงานของตัวเอง เมื่อจบระดับนี้: ปรับการค้นให้เข้ากับเอกสารของตัวเอง

เครื่องมือที่เริ่มใช้: BM25 (rank-bm25), FAISS, Gemini API, llm-eval, NumPy, sentence-transformers, SQL, SQLite

1. ดูค่าที่ปรับได้ของการค้น

   ```bash
   python hope.py config --all
   ```

   ควรเห็น: ค่า RAG_TOP_K, RAG_CHUNK_SIZE, RAG_CHUNK_OVERLAP และค่าปัจจุบัน
2. ค้นอย่างเดียวโดยไม่เรียก AI เพื่อดูว่าช่วงไหนถูกดึงมา

   ```bash
   python rag-pipeline/pipeline.py chat --search-only
   ```

   ควรเห็น: ช่วงเอกสารที่ค้นเจอเรียงตามอันดับ
3. เปลี่ยนจำนวนช่วงที่ส่งให้โมเดล แล้วถามคำถามเดิม

   ```bash
   python hope.py config set RAG_TOP_K 6
   ```

   ควรเห็น: แหล่งอ้างอิงมากขึ้น คำตอบอาจครบขึ้นหรือมีเรื่องไม่เกี่ยวปนมา
4. อ่านว่าการค้นรวมสองวิธีอย่างไร: ค้นด้วยคำ (BM25) และค้นด้วยความหมาย (embedding)
   ดู: ส่วนหัวของไฟล์ rag-pipeline/retrieve.py
5. ถามคำถามที่มีรหัสหรือชื่อเฉพาะ แล้วถามแบบใช้คำอื่นที่ความหมายเดียวกัน สังเกตว่าแบบไหนค้นเจอ

**ผ่านระดับนี้เมื่อ:** บอกได้ว่าเอกสารของคุณควรใช้ขนาดช่วงและจำนวนช่วงเท่าไร โดยมีคำถามตัวอย่างที่แสดงความต่าง

## ระดับ 3 สร้างระบบ

ทำให้คนอื่นใช้ได้ รันได้ต่อเนื่อง และดูแลต่อได้ เมื่อจบระดับนี้: รู้ทุกครั้งที่แก้ว่าคุณภาพการค้นและคำตอบดีขึ้นหรือแย่ลง

เครื่องมือที่เริ่มใช้: llama.cpp, PostgreSQL

1. อ่านรูปแบบชุดคำถามทดสอบ: แต่ละข้อมีคำถาม และไฟล์ต้นทางที่ควรค้นเจอ
   ดู: rag-pipeline/eval_cases_th.json
2. เขียนชุดคำถามของเอกสารคุณอย่างน้อย 10 ข้อ
3. วัดการค้น โดยยังไม่เรียกโมเดลตรวจ

   ```bash
   python rag-pipeline/pipeline.py eval --cases eval_cases_th.json --no-judge --min-recall 0.8
   ```

   ควรเห็น: ค่า recall และรหัสออก 1 ถ้าต่ำกว่าเกณฑ์
4. ดูว่า CI ของคู่มือรันอะไรทุกครั้งที่มีการแก้
   ดู: ไฟล์ใน .github/workflows
5. ดู schema สำหรับเก็บ log การเรียกโมเดล
   ดู: languages/sql/ai_logs_schema.sql

**ผ่านระดับนี้เมื่อ:** มีชุดคำถามของตัวเอง และมีตัวเลขก่อนกับหลังการแก้หนึ่งครั้ง

## ระดับ 4 เชี่ยวชาญ

ออกแบบ วัดผล และตัดสินใจเชิงระบบด้วยหลักฐาน เมื่อจบระดับนี้: ออกแบบระบบค้นหาสำหรับเอกสารจำนวนมากด้วยผลวัดจริง

เครื่องมือที่เริ่มใช้: Rust

1. อ่านวิธีตัดคำภาษาไทยที่การค้นด้วยคำใช้
   ดู: rag-pipeline/textutil.py
2. เปลี่ยนโมเดล embedding แล้วสร้างดัชนีใหม่ จากนั้นรันชุดคำถามเดิม

   ```bash
   python hope.py config set RAG_EMBED_MODEL ชื่อโมเดล
   ```

   ควรเห็น: ต้องรัน python hope.py docs ใหม่ก่อนวัด เพราะดัชนีเดิมใช้กับโมเดลใหม่ไม่ได้
3. เปิดการจัดอันดับซ้ำแล้ววัดอีกครั้ง

   ```bash
   python hope.py config set RAG_USE_RERANK true
   ```

   ควรเห็น: เทียบ recall และเวลาที่ใช้กับก่อนเปิด
4. ตรวจว่าเอกสารมีข้อมูลส่วนบุคคลไหม และข้อมูลนั้นถูกส่งออกนอกเครื่องไหม เทียบกับแถว T9 ใน threat model
   ดู: stack/THREAT-MODEL.md

**ผ่านระดับนี้เมื่อ:** มีตารางเทียบอย่างน้อยสองการตั้งค่าบนชุดคำถามเดียวกัน และเลือกหนึ่งแบบพร้อมเหตุผลจากตัวเลข

คำสั่งที่ไม่ต้องใช้โมเดลหรืออินเทอร์เน็ตถูกรันโดยชุดทดสอบของคู่มือทุกครั้งที่มีการแก้ ส่วนขั้นที่ต้องใช้โมเดล ไฟล์ของคุณ หรือการตัดสินใจของคุณ ต้องทำและตรวจด้วยตัวเอง
