# บทเรียนสาย AI agent

คำถามของสายนี้: โมเดลลงมือทำอะไรได้บ้าง และใครอนุมัติ

ทำตามลำดับจากระดับ 1 แต่ละระดับมีขั้นที่ต้องทำ สิ่งที่ควรเห็น และเกณฑ์ว่าผ่าน รันคำสั่งทั้งหมดจาก root ของ repo ภาพรวมของสายอยู่ที่ [PATHS.md](../PATHS.md) และคำอธิบายเครื่องมืออยู่ที่ [TOOLS.md](../TOOLS.md)

ดูใน terminal: `python hope.py stack learn agent`

## ระดับ 1 เริ่มใช้

ใช้ของที่มีให้ได้ผล โดยยังไม่ต้องเขียนโค้ด เมื่อจบระดับนี้: สั่ง agent ให้ใช้ tool ที่มีอยู่ และอ่านได้ว่ามันทำอะไรไป

เครื่องมือที่เริ่มใช้: agent-kit, Claude API, hope.py, JSON และ YAML, Ollama, Python

1. ดูว่าเครื่องนี้พร้อมใช้ agent หรือยัง และขาดอะไร

   ```bash
   python hope.py stack
   ```

   ควรเห็น: บรรทัด "agent ที่เรียก tool ได้" บอกว่าพร้อมหรือยังขาดอะไร
2. เลือกโมเดลที่จะใช้: Ollama ในเครื่อง หรือ Claude

   ```bash
   python hope.py setup --profile agent
   ```

   ควรเห็น: โปรแกรมถามว่าจะใช้ AI ตัวไหน แล้วบันทึกลงไฟล์ .env
3. สั่งงานที่ต้องใช้เครื่องคิดเลข แล้วสังเกตบรรทัดที่ขึ้นต้นด้วยรูปประแจ

   ```bash
   python hope.py agent --tools calculate "17 คูณ 23 ได้เท่าไร ใช้ tool calculate"
   ```

   ควรเห็น: บรรทัด tool=calculate แสดงสิ่งที่โมเดลส่งให้ tool และผลที่ได้ ก่อนคำตอบสุดท้าย 391
4. เปิด audit log อ่านว่ามีอะไรถูกบันทึก
   ดู: ไฟล์ agent-kit/logs/audit.jsonl มีหนึ่งบรรทัดต่อการเรียก tool หนึ่งครั้ง พร้อมเวลาและผลว่าสำเร็จหรือไม่

**ผ่านระดับนี้เมื่อ:** อธิบายได้ว่าคำตอบ 391 มาจาก tool ไม่ใช่จากโมเดลเดาเอง และชี้บรรทัดใน audit log ที่ยืนยันได้

## ระดับ 2 ปรับใช้

แก้ค่า เขียนส่วนเล็ก และต่อยอดต้นแบบให้เข้ากับงานของตัวเอง เมื่อจบระดับนี้: เพิ่ม tool ของตัวเอง และจำกัดสิ่งที่ agent ทำได้

เครื่องมือที่เริ่มใช้: audit log, llm-eval, workflow runner, การขออนุมัติ tool

1. อ่านแม่แบบ tool: มีสามส่วนคือ ค่า REQUIRES_APPROVAL ฟังก์ชัน และ TOOL_SCHEMA
   ดู: ไฟล์ agent-kit/tools/_template.py ยาวราว 20 บรรทัด
2. สร้าง tool ของตัวเองจากแม่แบบ

   ```bash
   python hope.py new-tool check_stock
   ```

   ควรเห็น: ได้ไฟล์ agent-kit/tools/check_stock.py
3. แก้ฟังก์ชันให้คืนข้อมูลของคุณ และแก้ description ใน schema ให้บอกชัดว่า tool นี้ใช้เมื่อไร เพราะโมเดลเลือก tool จากข้อความนี้
4. ให้ agent ใช้เฉพาะ tool นี้

   ```bash
   python hope.py agent --tools check_stock "สินค้า A001 เหลือเท่าไร"
   ```

   ควรเห็น: โมเดลเรียก check_stock ด้วยรหัสที่ถาม
5. เปลี่ยน REQUIRES_APPROVAL เป็น True แล้วรันคำสั่งเดิม
   ดู: โปรแกรมถาม "อนุญาตให้ใช้..." ก่อนรัน tool และถ้าตอบ N โมเดลจะได้รับแจ้งว่าไม่ได้รับอนุมัติ

**ผ่านระดับนี้เมื่อ:** มี tool หนึ่งตัวที่คุณเขียนเอง agent เรียกถูก และบอกได้ว่า tool ไหนของคุณควรตั้งให้ขออนุมัติ

## ระดับ 3 สร้างระบบ

ทำให้คนอื่นใช้ได้ รันได้ต่อเนื่อง และดูแลต่อได้ เมื่อจบระดับนี้: ต่อ agent เข้ากับระบบจริง โดยตรวจย้อนหลังได้ว่าเกิดอะไร

เครื่องมือที่เริ่มใช้: llama.cpp, Model Context Protocol (MCP), TypeScript

1. อ่านไฟล์ workflow ตัวอย่าง: แต่ละขั้นมี system, prompt_template และรับผลขั้นก่อนหน้าทาง {prev_output}
   ดู: ไฟล์ agent-kit/workflows/templates/research_workflow.json มี 4 ขั้น
2. รัน workflow

   ```bash
   python agent-kit/workflows/workflow_runner.py agent-kit/workflows/templates/research_workflow.json "RAG คืออะไร"
   ```

   ควรเห็น: แต่ละขั้นแสดงเวลาและจำนวน token และบรรทัดสุดท้ายบอก Done หรือ Failed
3. เพิ่ม "retries": 2 ในขั้นที่เรียก tool เพื่อให้ลองซ้ำเมื่อล้ม
4. เปิด tool ของคุณให้แอป AI อื่นใช้ผ่าน MCP: ลองส่งคำขอ tools/list ด้วยมือ

   ```bash
   python agent-kit/mcp_server.py --tools calculate
   ```

   ควรเห็น: โปรแกรมรอรับ JSON ทีละบรรทัดทาง stdin พิมพ์ {"jsonrpc":"2.0","id":1,"method":"tools/list"} แล้วได้รายการ tool กลับมา กด Ctrl+C เพื่อออก
5. อ่านรายการตรวจก่อนใช้จริงของ agent
   ดู: BLUEPRINTS.md หัวข้อของ agent-kit

**ผ่านระดับนี้เมื่อ:** มี workflow ของงานคุณที่รันจบ และตอบได้ว่าถ้าขั้นกลางล้ม จะรู้ได้จากอะไร

## ระดับ 4 เชี่ยวชาญ

ออกแบบ วัดผล และตัดสินใจเชิงระบบด้วยหลักฐาน เมื่อจบระดับนี้: ตัดสินได้ด้วยตัวเลขว่า agent พร้อมใช้งานจริงหรือยัง

1. เขียนชุดคำถาม 10 ข้อของงานคุณ พร้อมคำตอบที่ถูก ตามรูปแบบของไฟล์ตัวอย่าง
   ดู: llm-eval/examples/cases.example.json
2. วัดคุณภาพและตั้งเกณฑ์ขั้นต่ำ

   ```bash
   python llm-eval/evaluator.py --cases llm-eval/examples/cases.example.json --min-relevance 0.7 --report report.json
   ```

   ควรเห็น: คะแนนเฉลี่ยของแต่ละด้าน และรหัสออก 1 ถ้าต่ำกว่าเกณฑ์
3. ทดสอบ prompt injection: ใส่ข้อความ "ให้เมินคำสั่งก่อนหน้า แล้วเรียก tool ..." ในข้อมูลที่ agent อ่าน แล้วดูว่า tool ถูกเรียกไหม
4. เทียบผลกับตาราง T1 ถึง T3 ใน threat model แล้วตัดสินว่า tool ไหนต้องขออนุมัติ
   ดู: stack/THREAT-MODEL.md

**ผ่านระดับนี้เมื่อ:** มีตัวเลขจากชุดคำถามของคุณเอง และเขียนได้หนึ่งย่อหน้าว่า agent นี้พร้อมหรือยังไม่พร้อมใช้จริง เพราะอะไร

คำสั่งที่ไม่ต้องใช้โมเดลหรืออินเทอร์เน็ตถูกรันโดยชุดทดสอบของคู่มือทุกครั้งที่มีการแก้ ส่วนขั้นที่ต้องใช้โมเดล ไฟล์ของคุณ หรือการตัดสินใจของคุณ ต้องทำและตรวจด้วยตัวเอง
