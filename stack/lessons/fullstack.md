# บทเรียนสาย Full stack

คำถามของสายนี้: คนอื่นจะใช้งานนี้ผ่านอะไร

ทำตามลำดับจากระดับ 1 แต่ละระดับมีขั้นที่ต้องทำ สิ่งที่ควรเห็น และเกณฑ์ว่าผ่าน รันคำสั่งทั้งหมดจาก root ของ repo ภาพรวมของสายอยู่ที่ [PATHS.md](../PATHS.md) และคำอธิบายเครื่องมืออยู่ที่ [TOOLS.md](../TOOLS.md)

ดูใน terminal: `python hope.py stack learn fullstack`

## ระดับ 1 เริ่มใช้

ใช้ของที่มีให้ได้ผล โดยยังไม่ต้องเขียนโค้ด เมื่อจบระดับนี้: อธิบายได้ว่างานชิ้นหนึ่งประกอบด้วยส่วนไหนบ้าง

เครื่องมือที่เริ่มใช้: Claude API, Git, JSON และ YAML, Python, ไฟล์ .env

1. ดูว่าเครื่องนี้มีเครื่องมือของแต่ละชั้นหรือยัง

   ```bash
   python hope.py stack
   ```

   ควรเห็น: รายการแบ่งเป็นแกนหลัก โมเดล บริการและข้อมูล ภาษาเสริม
2. ดูเครื่องมือของสายนี้ที่ระดับ 1

   ```bash
   python hope.py stack tools --track fullstack --level 1
   ```

   ควรเห็น: Python, JSON และ YAML, Git, ไฟล์ .env และ Claude API
3. อ่านตารางชั้นของระบบ: หน้าจอ API ตรรกะ ข้อมูล ขึ้นระบบ เฝ้าระบบ
   ดู: stack/README.md หัวข้อ Full stack
4. เลือกงานหนึ่งอย่างที่คุณอยากทำ แล้วเขียนว่าแต่ละชั้นของงานนั้นคืออะไร

**ผ่านระดับนี้เมื่อ:** อธิบายงานหนึ่งชิ้นเป็นชั้นได้ครบ และบอกได้ว่าชั้นไหนคู่มือนี้มีต้นแบบให้

## ระดับ 2 ปรับใช้

แก้ค่า เขียนส่วนเล็ก และต่อยอดต้นแบบให้เข้ากับงานของตัวเอง เมื่อจบระดับนี้: เรียก API ที่มีอยู่จากโค้ดของตัวเอง

เครื่องมือที่เริ่มใช้: HTML และ CSS, JavaScript, Node.js, SQL, SQLite, unittest

1. ติดตั้งไลบรารีของ ai-api แล้วเปิดบริการ

   ```bash
   npm ci --prefix ai-api && npm start --prefix ai-api
   ```

   ควรเห็น: ข้อความ dpsxhope ai-api running on 127.0.0.1:3000
2. ตรวจว่าบริการยังอยู่ ด้วยคำขอ GET ที่ง่ายที่สุด

   ```bash
   curl http://127.0.0.1:3000/health
   ```

   ควรเห็น: {"status":"ok"}
3. ส่งคำถามด้วย POST พร้อม JSON

   ```bash
   curl -X POST http://127.0.0.1:3000/api/chat -H "Content-Type: application/json" -d "{\"message\": \"สวัสดี\"}"
   ```

   ควรเห็น: JSON ที่มี reply, usage และ model (หรือ 503 ถ้ายังไม่ได้ตั้ง ANTHROPIC_API_KEY)
4. อ่านโค้ดที่เรียกบริการจากโปรแกรม
   ดู: languages/typescript/client.ts
5. อ่านกติกา commit และ pull request ของคู่มือ แล้วลองดูประวัติการแก้

   ```bash
   git log --oneline -5
   ```

   ควรเห็น: ห้าบรรทัดล่าสุดของประวัติ และ CONTRIBUTING.md หัวข้อ Commit

**ผ่านระดับนี้เมื่อ:** เรียก API จากโค้ดหรือ curl ได้ และอธิบายได้ว่ารหัสสถานะ 400, 401, 429, 503 ของบริการนี้หมายถึงอะไร

## ระดับ 3 สร้างระบบ

ทำให้คนอื่นใช้ได้ รันได้ต่อเนื่อง และดูแลต่อได้ เมื่อจบระดับนี้: เปิดงาน AI เป็นบริการที่คนอื่นเรียกได้อย่างปลอดภัย

เครื่องมือที่เริ่มใช้: Docker, Docker Compose, Express, GitHub Actions, Go, npm audit, PostgreSQL, Redis, TypeScript

1. ตั้งรหัสของบริการ แล้วเปิดใหม่

   ```bash
   python hope.py config set APP_API_KEY
   ```

   ควรเห็น: โปรแกรมถามค่าโดยไม่แสดงตัวอักษร
2. เรียกโดยไม่ใส่รหัส

   ```bash
   curl -X POST http://127.0.0.1:3000/api/chat -H "Content-Type: application/json" -d "{\"message\": \"hi\"}"
   ```

   ควรเห็น: 401 Invalid API key
3. เปิดหน้าเว็บตัวอย่างที่ต่อกับบริการนี้ ตามขั้นในคู่มือของหน้าเว็บ

   ```bash
   python -m http.server 8080 --bind 127.0.0.1 --directory stack/examples/web
   ```

   ควรเห็น: หน้า "ถาม AI ผ่าน ai-api" ที่ http://127.0.0.1:8080 และต้องเพิ่มที่อยู่นี้ใน ALLOWED_ORIGINS ก่อน
4. อ่านว่าบริการตรวจสิทธิ์ จำกัดอัตรา และตรวจ input ตรงไหน
   ดู: ai-api/middleware และ ai-api/routes/chat.js
5. รันชุดทดสอบของบริการกับเซิร์ฟเวอร์จำลอง

   ```bash
   python hope.py test mock
   ```

   ควรเห็น: ข้อทดสอบของ ApiWithMock ผ่านครบ
6. อ่านรายการตรวจก่อนเปิดให้คนอื่นใช้
   ดู: BLUEPRINTS.md

**ผ่านระดับนี้เมื่อ:** มีบริการที่ต้องใช้รหัส มีหน้าเว็บที่เรียกบริการนั้นได้ และรายการตรวจใน BLUEPRINTS.md ของคุณติ๊กครบหรือรู้ว่าข้อไหนยังไม่ผ่าน

## ระดับ 4 เชี่ยวชาญ

ออกแบบ วัดผล และตัดสินใจเชิงระบบด้วยหลักฐาน เมื่อจบระดับนี้: มีหน้าเว็บที่ต่อกับบริการได้ และมีรายการสิ่งที่ยังขาดก่อนเปิดให้คนทั่วไปใช้

1. อ่านข้อจำกัดของหน้าเว็บตัวอย่าง: รหัสร่วม ไม่มีบัญชีผู้ใช้
   ดู: stack/examples/web/README.md หัวข้อ ข้อจำกัด
2. ห่อบริการเป็นภาพ Docker แล้วรัน (ต้องเปิด Docker ก่อน ยังไม่ได้ทดสอบในคู่มือ)

   ```bash
   docker build -t dpsxhope-ai-api ai-api
   ```

   ควรเห็น: ภาพชื่อ dpsxhope-ai-api
3. อ่านไฟล์ที่ประกาศหลายบริการให้รันด้วยกัน
   ดู: languages/yaml/ai_stack.docker-compose.yml
4. ตรวจช่องโหว่ของไลบรารีก่อนเปิดให้คนอื่นใช้

   ```bash
   python hope.py audit
   ```

   ควรเห็น: ผลของ npm audit และ pip-audit
5. อ่านแถว T5 ใน threat model แล้วเขียนว่าระบบของคุณต้องมีอะไรเพิ่มก่อนเปิดออกนอกเครื่อง: บัญชีผู้ใช้ TLS การเฝ้าระบบ
   ดู: stack/THREAT-MODEL.md

**ผ่านระดับนี้เมื่อ:** มีรายการสิ่งที่ระบบของคุณยังขาดก่อนเปิดให้คนทั่วไปใช้ เรียงตามความสำคัญ (คู่มือนี้ยังไม่มีต้นแบบของบัญชีผู้ใช้ การขึ้น cloud และการแจ้งเตือน)

คำสั่งที่ไม่ต้องใช้โมเดลหรืออินเทอร์เน็ตถูกรันโดยชุดทดสอบของคู่มือทุกครั้งที่มีการแก้ ส่วนขั้นที่ต้องใช้โมเดล ไฟล์ของคุณ หรือการตัดสินใจของคุณ ต้องทำและตรวจด้วยตัวเอง
