ทำตามลำดับจากระดับ 1 แต่ละระดับมีขั้นที่ต้องทำ สิ่งที่ควรเห็น และเกณฑ์ว่าผ่าน รันคำสั่งทั้งหมดจาก root ของ repo ภาพรวมของสายอยู่ที่ [PATHS.md](../PATHS.md) และคำอธิบายเครื่องมืออยู่ที่ [TOOLS.md](../TOOLS.md)

## ระดับ 1 เริ่มใช้

ใช้ของที่มีให้ได้ผล โดยยังไม่ต้องเขียนโค้ด เมื่อจบระดับนี้: อ่านผลทดสอบในคู่มือนี้ได้ว่าตัวเลขหมายถึงอะไร

เครื่องมือที่เริ่มใช้: Python, เดโมจากหัวใจสู่กลไก

1. ดูรายการผลทดสอบของต้นแบบ แล้วหาตัวเลขที่เป็นสัดส่วน เช่น 28/30

   ```bash
   python hope.py list -v
   ```

   ควรเห็น: บรรทัด "ไฟล์ถูกอันดับ 1 = 28/30" ของ rag-pipeline
2. แปลง 28/30 และ 30/30 เป็นร้อยละด้วยมือ แล้วตรวจด้วย tool

   ```bash
   python -c "print(round(28/30*100, 1))"
   ```

   ควรเห็น: 93.3
3. ตอบคำถาม: ถ้าชุดทดสอบมี 30 ข้อ ผิดเพิ่มหนึ่งข้อทำให้ร้อยละเปลี่ยนเท่าไร แล้วถ้ามี 300 ข้อ
4. อ่านว่าตัวเลขแต่ละตัวมาจากชุดทดสอบไหน และอะไรยังไม่ได้ทดสอบ
   ดู: catalog.json ช่อง verified และ unverified

**ผ่านระดับนี้เมื่อ:** อ่านผลทดสอบแล้วบอกได้ว่าวัดจากกี่ข้อ และตัวเลขนั้นเชื่อได้แค่ไหนจากจำนวนข้อ

## ระดับ 2 ปรับใช้

แก้ค่า เขียนส่วนเล็ก และต่อยอดต้นแบบให้เข้ากับงานของตัวเอง เมื่อจบระดับนี้: เข้าใจว่าทำไมการค้นได้ผลแบบนี้ และวัดได้ว่าดีแค่ไหน

เครื่องมือที่เริ่มใช้: BM25 (rank-bm25), FAISS, NumPy, robokit, sentence-transformers

1. คำนวณความใกล้กันของเวกเตอร์สองตัวด้วยมือ: (1, 0) กับ (1, 1) โดย cosine = ผลคูณจุด หารด้วยผลคูณของความยาว

   ```bash
   python -c "import math; print(round(1/(1*math.sqrt(2)), 4))"
   ```

   ควรเห็น: 0.7071
2. อ่านว่าการค้นใช้เวกเตอร์อย่างไร และรวมกับการให้คะแนนคำอย่างไร
   ดู: ส่วนหัวของ rag-pipeline/retrieve.py: dense (FAISS) + sparse (BM25) แล้วรวมอันดับ
3. คำนวณ recall ด้วยมือ: ถ้าคำตอบที่ถูกมี 6 ชิ้น และระบบค้นเจอ 5 ชิ้น

   ```bash
   python -c "print(round(5/6, 2))"
   ```

   ควรเห็น: 0.83
4. อธิบายว่าทำไมคำที่พบในทุกเอกสาร เช่น "และ" ควรได้น้ำหนักน้อยกว่าคำที่พบในเอกสารเดียว

**ผ่านระดับนี้เมื่อ:** อธิบายด้วยคำของตัวเองได้ว่าทำไมค้นด้วยความหมายพลาดรหัสสินค้า และทำไมค้นด้วยคำพลาดคำพ้องความหมาย

## ระดับ 3 สร้างระบบ

ทำให้คนอื่นใช้ได้ รันได้ต่อเนื่อง และดูแลต่อได้ เมื่อจบระดับนี้: คำนวณและตรวจค่าควบคุมกับระยะหยุดด้วยมือได้

1. คำนวณระยะหยุดด้วยมือ: ความเร็ว 0.5 m/s เวลาตอบสนอง 0.2 s อัตราหน่วง 2 m/s² ด้วยสูตร v·t + v²/(2a)
   ดู: 0.5 × 0.2 = 0.1 และ 0.25 / 4 = 0.0625 รวม 0.1625 m
2. ตรวจกับเครื่องมือ

   ```bash
   python hope.py robot stop --speed 0.5 --react 0.2 --decel 2.0 --available 0.4 --json
   ```

   ควรเห็น: react_distance 0.1, brake_distance 0.0625, total 0.1625
3. เพิ่มความเร็วเป็นสองเท่า แล้วดูว่าระยะเบรกเพิ่มกี่เท่า

   ```bash
   python hope.py robot stop --speed 1.0 --react 0.2 --decel 2.0 --available 0.4 --json
   ```

   ควรเห็น: brake_distance เป็น 0.25 คือสี่เท่า เพราะขึ้นกับความเร็วยกกำลังสอง และ ok เป็น false (รหัสออก 2) เพราะหยุดไม่ทัน
4. ดูผลของ PID เมื่อค่าที่วัดคลาด

   ```bash
   python hope.py robot tune --mass 2 --friction 4 --max-force 40
   ```

   ควรเห็น: ตารางกรณีที่มวลและแรงเสียดทานคลาด ±30 % และค่าที่เกินเป้าของแต่ละกรณี
5. อ่านคำอธิบายของ P, I, D ในบทที่ 1
   ดู: fields/robotics/01-heart-to-mechanism.md

**ผ่านระดับนี้เมื่อ:** คำนวณระยะหยุดด้วยมือแล้วตรงกับเครื่องมือ และอธิบายได้ว่าทำไมความเร็วเพิ่มสองเท่าอันตรายกว่าสองเท่า

## ระดับ 4 เชี่ยวชาญ

ออกแบบ วัดผล และตัดสินใจเชิงระบบด้วยหลักฐาน เมื่อจบระดับนี้: อ่านงานวิจัยและตัดสินได้ว่าผลที่อ้างน่าเชื่อแค่ไหน

เครื่องมือที่เริ่มใช้: Qiskit

1. อ่านตัวอย่างวงจรควอนตัม: สถานะของ qubit เป็นเวกเตอร์ และเกตเป็นเมทริกซ์
   ดู: domains/quantum/qiskit_intro.py (ต้องติดตั้ง Qiskit ถ้าจะรัน)
2. คำนวณด้วยมือ: เกต Hadamard คูณกับสถานะ (1, 0) ได้อะไร

   ```bash
   python -c "import math; h=1/math.sqrt(2); print(round(h*h, 2))"
   ```

   ควรเห็น: 0.5 คือความน่าจะเป็นที่จะวัดได้ 0 หลังผ่านเกต
3. ถามกับผลทดสอบใด ๆ ในคู่มือ: วัดจากกี่ข้อ ชุดทดสอบเขียนโดยใคร และผลจะเปลี่ยนไหมถ้าเปลี่ยนชุดทดสอบ
   ดู: catalog.json ช่อง unverified ของ rag-pipeline บอกว่าชุดทดสอบเขียนโดยผู้ดูแลเอง
4. เลือกงานวิจัยหนึ่งชิ้นในรายการอ้างอิงของสาขาหุ่นยนต์ แล้วหาว่าผลหลักวัดอย่างไร
   ดู: fields/robotics/README.md

**ผ่านระดับนี้เมื่อ:** อ่านผลที่อ้างในงานหนึ่งชิ้นแล้วเขียนได้ว่าหลักฐานคืออะไร และอะไรที่งานนั้นไม่ได้วัด (คู่มือนี้ยังไม่มีบทเรียนคณิตศาสตร์ระดับนี้ มีแต่จุดที่ใช้)

คำสั่งที่ไม่ต้องใช้โมเดลหรืออินเทอร์เน็ตถูกรันโดยชุดทดสอบของคู่มือทุกครั้งที่มีการแก้ ส่วนขั้นที่ต้องใช้โมเดล ไฟล์ของคุณ หรือการตัดสินใจของคุณ ต้องทำและตรวจด้วยตัวเอง
