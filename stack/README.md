# แผนที่ stack

ภาษา เครื่องมือ และรากฐานความรู้ที่ใช้สร้างงาน AI ในคู่มือนี้ บอกว่าแต่ละชิ้นอยู่ตรงไหน ใช้เมื่อไร และตอนนี้ทดสอบถึงไหนแล้ว

**สถานะ: v0.3 (2026-11-12)** เครื่องมือและภาษา 49 ชิ้นถูกจัดเป็นกลุ่ม แยกตามสายและระดับ พร้อมคำอธิบายและตัวอย่างในคู่มือครบทุกชิ้น และทุกสายมีบทเรียนเป็นขั้นครบ 4 ระดับ บทเรียนของ Full stack, Cybersecurity, คณิตศาสตร์ และปรัชญา เป็นขั้นที่พาใช้ของที่มีในคู่มือกับแบบฝึกคิด ยังไม่ใช่หลักสูตรเต็มของสาขานั้น และยังไม่ได้ให้ผู้เชี่ยวชาญตรวจ

## เริ่มจากเครื่องของคุณ

```bash
python hope.py stack
```

คำสั่งนี้ดูว่าเครื่องมีภาษาและเครื่องมืออะไร แล้วบอกว่าส่วนไหนของคู่มือใช้ได้แล้ว ส่วนไหนยังขาดอะไร ใช้ไลบรารีมาตรฐานของ Python อย่างเดียว เพิ่ม `--json` ถ้าจะเอาผลไปใช้ต่อ คำสั่งตรวจแค่ว่ามีเครื่องมือและค่าตั้งครบ ไม่ได้ลองเรียกโมเดลจริง

จากนั้นดูแผนที่ได้ห้าแบบ

```bash
python hope.py stack map                          # ภาพรวม: สาย × ระดับ
python hope.py stack path automation              # สายเดียว ไล่ทีละระดับ (เพิ่ม --level 2 ได้)
python hope.py stack tools --track security       # เครื่องมือ กรองตาม --group --track --level
python hope.py stack show ollama                  # เครื่องมือชิ้นเดียว: คืออะไร ใช้เมื่อไร
python hope.py stack learn automation --level 1   # บทเรียนเป็นขั้นของสายนั้น
```

## วิธีอ่านแผนที่

แผนที่นี้แบ่งสามแกนที่แยกจากกัน เครื่องมือชิ้นหนึ่งมีกลุ่มเดียว มีระดับเดียว แต่อยู่ได้หลายสาย

| แกน | ตอบคำถาม | ตัวอย่าง |
|---|---|---|
| **กลุ่ม** | เครื่องมือนี้เป็นของชนิดไหน | ภาษา, โมเดล, ข้อมูล, ความปลอดภัย |
| **สาย** | เป้าหมายของงานคืออะไร | AI agent, งานอัตโนมัติ, Full stack |
| **ระดับ** | ต้องลึกแค่ไหนถึงจะเริ่มใช้ | 1 เริ่มใช้ ถึง 4 เชี่ยวชาญ |

เอกสารสองหน้านี้สร้างจากคลังข้อมูลเดียวกัน ([stack.json](stack.json)) จึงตรงกันเสมอ

- [TOOLS.md](TOOLS.md): เครื่องมือและภาษาทุกชิ้น จัดตามกลุ่ม พร้อมคำอธิบายว่าคืออะไรและใช้เมื่อไร
- [PATHS.md](PATHS.md): ทุกสาย ไล่ทีละระดับ พร้อมความรู้ที่ควรมี สิ่งที่ทำได้เมื่อจบ และเนื้อหาในคู่มือ
- บทเรียนเป็นขั้นของแต่ละสาย: [AI agent](lessons/agent.md), [งานอัตโนมัติ](lessons/automation.md), [ข้อมูลและการค้นหา](lessons/data.md), [Full stack](lessons/fullstack.md), [Cybersecurity](lessons/security.md), [หุ่นยนต์](lessons/robotics.md), [คณิตศาสตร์](lessons/math.md), [ปรัชญา](lessons/philosophy.md) แต่ละระดับมีขั้นที่ต้องทำ สิ่งที่ควรเห็น และเกณฑ์ว่าผ่าน

### ระดับ

| ระดับ | ชื่อ | ความหมาย |
|---|---|---|
| 1 | เริ่มใช้ | ใช้ของที่มีให้ได้ผล โดยยังไม่ต้องเขียนโค้ด |
| 2 | ปรับใช้ | แก้ค่า เขียนส่วนเล็ก และต่อยอดต้นแบบให้เข้ากับงานของตัวเอง |
| 3 | สร้างระบบ | ทำให้คนอื่นใช้ได้ รันได้ต่อเนื่อง และดูแลต่อได้ |
| 4 | เชี่ยวชาญ | ออกแบบ วัดผล และตัดสินใจเชิงระบบด้วยหลักฐาน |

ไม่จำเป็นต้องไปถึงระดับ 4 ทุกสาย เลือกสายตามเป้าหมาย แล้วไปให้ลึกเท่าที่งานต้องการ

### สาย

| สาย | คำถามของสาย | มีอะไรในคู่มือแล้ว |
|---|---|---|
| AI agent | โมเดลลงมือทำอะไรได้บ้าง และใครอนุมัติ | [`agent-kit`](../agent-kit/README.md) มีต้นแบบถึงระดับ 3 |
| งานอัตโนมัติ | งานนี้เริ่มเองได้ไหม โดยไม่ต้องมีคนสั่งทุกครั้ง | [`automate.py`](../agent-kit/README.md#งานอัตโนมัติ) มีต้นแบบถึงระดับ 3 |
| ข้อมูลและการค้นหา | คำตอบมาจากข้อมูลไหน และดีแค่ไหน | [`rag-pipeline`](../rag-pipeline/README.md), [`llm-eval`](../llm-eval/README.md) |
| Full stack | คนอื่นจะใช้งานนี้ผ่านอะไร | [`ai-api`](../ai-api/README.md), [หน้าเว็บตัวอย่าง](examples/web/README.md), [`languages`](../languages/README.md) |
| Cybersecurity | อะไรผิดพลาดได้ และกันไว้ตรงไหน | [Threat model](THREAT-MODEL.md), `python hope.py audit` และด่านในต้นแบบแต่ละชิ้น |
| หุ่นยนต์ | คำสั่งจากโมเดลกลายเป็นการเคลื่อนที่ที่ปลอดภัยได้อย่างไร | [แผนที่สาขาหุ่นยนต์](../fields/robotics/README.md) |
| คณิตศาสตร์ | ทำไมวิธีนี้ถึงใช้ได้ | แบบฝึกคำนวณด้วยมือที่ตรวจกับเครื่องมือได้ ยังไม่มีเนื้อหาสอนทฤษฎี |
| ปรัชญา | เรารู้ได้อย่างไรว่าใช้ได้ และใครรับผิดชอบ | แบบฝึกคิดที่ผูกกับการออกแบบในคู่มือ ยังไม่มีเนื้อหาสอนทฤษฎี |

คณิตศาสตร์และปรัชญาเป็นรากฐานของทุกสาย ส่วน Cybersecurity ต้องคิดในทุกสาย หัวข้อถัดจากนี้ขยายความแต่ละสาย

## AI agent

agent คือโมเดลที่เรียกเครื่องมือได้เอง แล้วใช้ผลที่ได้ตัดสินใจขั้นต่อไป ใน [`agent-kit`](../agent-kit/README.md) แยกเป็นสี่ชิ้น

| ชิ้น | หน้าที่ | ไฟล์ |
|---|---|---|
| ชั้นกลางของโมเดล | คุยกับ Claude หรือ Ollama ด้วยรูปแบบเดียว | `agent-kit/llm.py` |
| ทะเบียน tool | ค้นหา tool ตรวจสิทธิ์ ขออนุมัติ และเขียน audit log | `agent-kit/tools/` |
| วงทำงาน | ถามโมเดล รัน tool ส่งผลกลับ จนจบหรือครบจำนวนรอบ | `agent-kit/agent.py` |
| workflow | หลายขั้นต่อกันตามลำดับ ลองซ้ำได้เมื่อขั้นหนึ่งล้ม | `agent-kit/workflows/` |

หลักเลือกใช้

- งานที่ขั้นตอนตายตัว ใช้ workflow หรืองานอัตโนมัติ ผลคาดเดาได้กว่าและตรวจง่ายกว่า
- งานที่ต้องเลือกเครื่องมือตามสถานการณ์ ใช้ agent และจำกัด tool ด้วย `--tools`
- tool ที่แก้ข้อมูล ส่งข้อความ หรือจ่ายเงิน ตั้ง `REQUIRES_APPROVAL = True` เสมอ
- ข้อมูลที่ห้ามออกจากเครื่อง ใช้ Ollama (`LLM_PROVIDER=ollama`) และเลือกโมเดลที่รองรับ tools ซึ่ง `python hope.py stack` แสดงรายชื่อให้

## งานอัตโนมัติ

เริ่มจากขั้นล่างสุดที่แก้ปัญหาได้ แล้วค่อยขยับขึ้นเมื่อจำเป็น ขั้นที่สูงขึ้นมีของต้องดูแลมากขึ้น

| ขั้น | ทำอย่างไร | เหมาะเมื่อ | สถานะในคู่มือ |
|---|---|---|---|
| 1 | รันคำสั่งเองทีละครั้ง | งานนานๆ ครั้ง ยังไม่แน่ใจขั้นตอน | ใช้ได้ |
| 2 | ไฟล์งาน JSON รันด้วย `python hope.py auto run ชื่องาน` | งานซ้ำที่ขั้นตอนนิ่งแล้ว เช่น ไฟล์เข้าโฟลเดอร์แล้วสรุป | ใช้ได้ มีชุดทดสอบ |
| 3 | ให้ระบบปฏิบัติการเรียกขั้น 2 ตามเวลา (Task Scheduler, cron) หรือใช้ `auto loop` | งานที่ต้องเกิดเองทุกวันหรือทุกชั่วโมง | `auto loop` ใช้ได้ `auto schedule` สร้างคำสั่งตั้งเวลาให้ แต่ยังไม่ได้ลองตั้งเวลาจริง |
| 4 | รับงานจากบริการอื่น วัดผล และบริการที่รันตลอดพร้อมคิวงาน | หลายคนใช้พร้อมกัน งานยาวหลายชั่วโมง | มี `auto serve` (รับไฟล์ทาง HTTP ในเครื่อง) และ `auto report` (วัดผลจาก log) ส่วนคิวงานและการกู้กลางขั้นยังไม่มี |

ทุกงานอัตโนมัติควรตอบได้สี่ข้อก่อนปล่อยให้รันเอง: ดูก่อนได้ไหมว่าจะทำอะไร (`--dry-run`), ทำซ้ำแล้วผลไม่ซ้อนกันไหม, ล้มแล้วรู้ได้อย่างไร (log และรหัสออก), และหยุดมันได้อย่างไร รายละเอียดอยู่ใน [agent-kit](../agent-kit/README.md#งานอัตโนมัติ)

## ภาษาและเครื่องมือ

คู่มือนี้ใช้ Python เป็นหลัก ภาษาอื่นมีเป็นตัวอย่างสำหรับงานที่ Python ไม่ใช่ตัวเลือกแรก คำอธิบายของทุกภาษาและเครื่องมือ พร้อมระดับที่เริ่มต้องใช้และสายที่เกี่ยวข้อง อยู่ที่ [TOOLS.md](TOOLS.md) ซึ่งแบ่งเป็น 9 กลุ่ม

| กลุ่ม | มีอะไร |
|---|---|
| ภาษา | Python, JSON และ YAML, SQL, Bash, JavaScript, HTML และ CSS, TypeScript, Go, Rust, C++ |
| โมเดล | Ollama, Claude API, Gemini API, sentence-transformers, llama.cpp |
| ข้อมูลและการค้นหา | pypdf, BM25, FAISS, SQLite, PostgreSQL, Redis |
| agent และงานอัตโนมัติ | agent-kit, automate.py, workflow runner, Task Scheduler และ cron, n8n, GitHub Actions, Model Context Protocol (MCP) |
| เว็บและบริการ | Node.js, Express, Docker, Docker Compose |
| คุณภาพและการทดสอบ | hope.py, Git, unittest, llm-eval |
| ความปลอดภัย | ไฟล์ .env, การขออนุมัติ tool, audit log, ด่านตรวจคำสั่ง, npm audit, pip-audit |
| หุ่นยนต์และการจำลอง | เดโมจากหัวใจสู่กลไก, robokit, MuJoCo, Gazebo, ROS 2 |
| การคำนวณ | NumPy, Qiskit |

รายการนี้คัดเฉพาะของที่คู่มือใช้จริง หรือของที่สายนั้นต้องเจอในระดับถัดไป ไม่ใช่รายการเครื่องมือทั้งหมดที่มีในโลก เครื่องมือที่ยังไม่มีตัวอย่างในคู่มือถูกระบุไว้ชัดในตาราง สถานะการทดสอบของตัวอย่างแต่ละภาษาอยู่ใน [languages/README.md](../languages/README.md)

## Full stack

งานที่คนอื่นใช้ได้จริงมีมากกว่าโมเดล ตารางนี้ไล่จากสิ่งที่ผู้ใช้เห็นลงไปถึงสิ่งที่อยู่เบื้องหลัง พร้อมบอกว่าคู่มือมีอะไรแล้ว

| ชั้น | หน้าที่ | ในคู่มือ |
|---|---|---|
| หน้าจอผู้ใช้ | รับคำถาม แสดงคำตอบและแหล่งอ้างอิง | เมนูใน terminal (`python hope.py`) และ[หน้าเว็บตัวอย่าง](examples/web/README.md)ที่ต่อกับ ai-api |
| API | รับคำขอ ตรวจสิทธิ์ จำกัดอัตรา ตรวจ input | [`ai-api`](../ai-api/README.md): Bearer key, CORS allowlist, rate limit |
| ตรรกะของงาน | RAG, agent, workflow, งานอัตโนมัติ | `rag-pipeline`, `agent-kit` |
| ข้อมูล | เอกสาร ดัชนีค้นหา log | ดัชนีในเครื่องของ `rag-pipeline`, schema ใน `languages/sql` |
| ขึ้นระบบ | รวมบริการให้รันด้วยกัน | `ai-api/Dockerfile`, `languages/yaml` (ตรวจ config แล้ว ยังไม่ได้ขึ้นจริง) |
| เฝ้าระบบ | รู้เมื่อพังหรือคุณภาพตก | audit log ของ agent, `llm-eval` เป็นด่านใน CI |

สิ่งที่ยังไม่มี: ระบบบัญชีผู้ใช้ การขึ้นระบบบน cloud จริง และการเฝ้าระบบแบบมีการแจ้งเตือน ก่อนเปิดให้ผู้อื่นใช้ อ่าน [คู่มือนำไปใช้จริง](../BLUEPRINTS.md)

## Cybersecurity

ส่วนนี้เป็นความปลอดภัยเชิงป้องกันสำหรับระบบที่คุณสร้างเอง ไม่ใช่คู่มือเจาะระบบ ระบบ AI มีความเสี่ยงของซอฟต์แวร์ทั่วไปทั้งหมด และเพิ่มอีกข้อหนึ่ง คือข้อความที่โมเดลอ่านอาจมีคำสั่งแฝงมา (prompt injection)

| ความเสี่ยง | สิ่งที่คู่มือทำไว้แล้ว | ยังไม่ได้ทำ |
|---|---|---|
| โมเดลถูกหลอกหรือเพ้อ แล้วลงมือทำ | tool ที่เสี่ยงต้องมีคนอนุมัติ, งานอัตโนมัติต้องระบุ `allow_tools` เอง, ขั้นถาม AI ในงานอัตโนมัติไม่ได้ tool ถ้าไม่ระบุ, [ด่านตรวจคำสั่งของ robokit](../fields/robotics/robokit/README.md) แยกจากโมเดล | ไม่มี sandbox แยก tool ออกจากเครื่อง |
| ความลับรั่ว | `.env` ไม่ขึ้น Git, `config set` รับ key โดยไม่ค้างในประวัติคำสั่ง, audit log ตัดข้อความยาวออก | ไม่มีการเข้ารหัสไฟล์ในเครื่อง และ input สั้นของ tool ยังถูกบันทึกทั้งหมด |
| เขียนหรืออ่านไฟล์นอกพื้นที่ | งานอัตโนมัติเขียนได้เฉพาะในพื้นที่ทำงานของงาน, `text_search` ค้นได้เฉพาะในโฟลเดอร์ที่เริ่มรัน | tool ที่คุณเขียนเองต้องตรวจเอง |
| บริการถูกเรียกโดยคนที่ไม่ควรเรียก | `ai-api` บังคับ Bearer key, จำกัดอัตรา, CORS allowlist และไม่ยอมเปิดรับจากภายนอกถ้าไม่ได้ตั้ง key | key เดียวใช้ร่วมกัน ไม่ใช่ระบบบัญชีผู้ใช้ |
| ข้อมูลออกจากเครื่องโดยไม่ตั้งใจ | ใช้ Ollama ได้ทั้งถามเอกสาร agent และงานอัตโนมัติ และมีข้อความเตือนเมื่อใช้ Claude | ยังไม่มีการคัดข้อมูลส่วนบุคคลออกก่อนส่ง |
| ไลบรารีภายนอกมีช่องโหว่ | `python hope.py audit` รัน npm audit และ pip-audit; `ai-api` ล็อกรุ่นด้วย `package-lock.json` | ฝั่ง Python ยังไม่ล็อกรุ่น และการตรวจประจำสัปดาห์ใน GitHub Actions ยังไม่เคยรัน |

ภาพรวมของภัยทั้งระบบ ลำดับสิ่งที่ควรแก้ และแผนเมื่อเกิดเหตุ อยู่ใน [Threat model](THREAT-MODEL.md) สิ่งที่ยังไม่มี: sandbox ของ tool และการทดสอบเจาะ ตารางนี้บอกสิ่งที่โค้ดทำ ไม่ได้รับรองว่าระบบที่คุณสร้างต่อจะปลอดภัย

## คณิตศาสตร์

ไม่ต้องรู้ทั้งหมดก่อนเริ่ม แต่เมื่อผลออกมาแปลก คณิตศาสตร์ข้างล่างคือสิ่งที่ช่วยให้รู้ว่าแปลกเพราะอะไร ตารางนี้ชี้ว่าแต่ละเรื่องถูกใช้ตรงไหนในคู่มือ

| เรื่อง | ใช้ตอบคำถามอะไร | ใช้ตรงไหนในคู่มือ |
|---|---|---|
| เวกเตอร์และพีชคณิตเชิงเส้น | ข้อความสองชิ้นมีความหมายใกล้กันแค่ไหน | การค้นด้วย embedding ใน `rag-pipeline/retrieve.py` |
| ความน่าจะเป็นและสถิติ | คำนี้สำคัญกับเอกสารนี้แค่ไหน ผลทดสอบเชื่อได้แค่ไหน | การจัดอันดับ BM25, ค่า recall ในชุดทดสอบของ `rag-pipeline`, คะแนนใน `llm-eval` |
| แคลคูลัสและสมการการเคลื่อนที่ | สั่งมอเตอร์อย่างไรให้ถึงเป้าโดยไม่เลย หยุดทันไหม | PID และระยะหยุดใน [robokit](../fields/robotics/robokit/README.md) |
| ตรรกะและเซต | คำสั่งนี้อยู่ในขอบเขตที่อนุญาตไหม | ด่านตรวจของ robokit, การตรวจไฟล์งานอัตโนมัติ |
| จำนวนเชิงซ้อนและพีชคณิตเชิงเส้น | สถานะของ qubit เปลี่ยนอย่างไร | `domains/quantum/qiskit_intro.py` |

บทเรียนของสายนี้ ([lessons/math.md](lessons/math.md)) เป็นแบบฝึกคำนวณด้วยมือแล้วตรวจกับเครื่องมือ ยังไม่มีเนื้อหาสอนทฤษฎี ตารางเป็นแผนที่ว่าควรเรียนเรื่องไหนเมื่อติดตรงไหน

## ปรัชญา

ปรัชญาในที่นี้คือคำถามที่ต้องตอบก่อนเชื่อผลของระบบ และก่อนปล่อยให้ระบบลงมือทำแทนคน แต่ละข้อมีผลต่อการออกแบบในคู่มือนี้โดยตรง

| สาขา | คำถาม | ผลต่อการออกแบบในคู่มือ |
|---|---|---|
| ตรรกะ | ข้อสรุปนี้ตามมาจากหลักฐานจริงไหม | ด่านตรวจใช้กฎที่ตรวจได้ แยกจากโมเดลที่ให้เหตุผลแบบน่าจะเป็น |
| ญาณวิทยา (เรารู้ได้อย่างไร) | อะไรพิสูจน์แล้ว อะไรแค่เชื่อ | ทุกต้นแบบแยกรายการ "ทดสอบแล้ว" กับ "ยังไม่ได้ทดสอบ" (`python hope.py list -v`), คำตอบจากเอกสารมีแหล่งอ้างอิง, ไม่ใช้ความมั่นใจที่โมเดลรายงานเองเป็นด่านเดียว |
| จริยศาสตร์ | เมื่อ agent ทำผิด ใครรับผิดชอบ | คนเป็นผู้อนุมัติ tool ที่เสี่ยง, `allow_tools` คือการตัดสินใจของเจ้าของงานที่ถูกบันทึกไว้, audit log บอกว่าอะไรถูกทำเมื่อไร |
| ปรัชญาภาษาและจิต | โมเดล "เข้าใจ" คำสั่งจริงไหม | ถือว่าข้อความจากเอกสารเป็นข้อมูล ไม่ใช่คำสั่ง และตรวจผลที่ปลายทาง ไม่ตรวจที่เจตนา |

บทเรียนของสายนี้ ([lessons/philosophy.md](lessons/philosophy.md)) เป็นแบบฝึกคิดที่ผูกกับระบบของคุณ ยังไม่มีเนื้อหาสอนทฤษฎี เครื่องมือคิดเชิงลึกอยู่ในแผนชั้น Thinker OS ของ [ROADMAP](../ROADMAP.md)

## ยังไม่ได้ทดสอบ

- `python hope.py stack` ทดสอบบน Windows เครื่องเดียว และด้วยข้อมูลเครื่องจำลองในชุดทดสอบ ยังไม่ได้ลองบน macOS, Linux หรือ Termux
- agent กับ Ollama ทดสอบกับโมเดลตระกูล gemma ในเครื่องหนึ่งคำถาม คุณภาพการเลือก tool ของโมเดลอื่นยังไม่ได้วัด
- คำสั่งตั้งเวลาที่ `auto schedule` สร้างให้ ยังไม่ได้ลองตั้งเวลาจริงทั้ง Task Scheduler และ cron
- หลักเลือกภาษาและระดับของเครื่องมือแต่ละชิ้นเป็นความเห็นตั้งต้นของคู่มือ ไม่ได้มาจากการวัดเปรียบเทียบ และยังไม่ได้ให้ผู้เชี่ยวชาญแต่ละสายตรวจ
- ตัวอย่างที่ยังไม่ได้ลองกับของจริง: MCP server ยังไม่ได้ต่อกับแอป AI จริงและทำตามสเปกรุ่น 2025-11-25 (ไม่ใช่รุ่นล่าสุด), ช่องรับไฟล์ยังไม่ได้ลองกับ n8n, ตัวอย่าง C++ ยังไม่ได้คอมไพล์บนเครื่องผู้ดูแล (ชุดทดสอบคอมไพล์เมื่อมีตัวคอมไพล์), หน้าเว็บทดสอบกับเซิร์ฟเวอร์จำลองในเบราว์เซอร์เดียว และ MuJoCo, Gazebo, ROS 2 ยังไม่ได้ลอง
- บทเรียน: คำสั่งที่ไม่ต้องใช้โมเดลถูกรันโดยชุดทดสอบ ส่วนขั้นที่ต้องใช้โมเดล ไฟล์ของผู้เรียน หรือการตัดสินใจ ยังไม่มีผู้เรียนจริงลองทำตาม
