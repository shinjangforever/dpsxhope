# หน้าเว็บตัวอย่าง: ถาม AI ผ่าน ai-api

หน้าเว็บหน้าเดียว ([index.html](index.html)) เขียนด้วย HTML, CSS และ JavaScript ล้วน ไม่มีไลบรารีและไม่มีขั้น build ใช้ดูว่าชั้น "หน้าจอผู้ใช้" ต่อกับชั้น "API" อย่างไร

## รัน

เปิดสอง terminal ที่ root ของ repo

```bash
# 1) บริการ ai-api: ตั้งให้ยอมรับคำขอจากที่อยู่ของหน้าเว็บ
python hope.py config set ALLOWED_ORIGINS http://127.0.0.1:8080
python hope.py config set APP_API_KEY
npm start --prefix ai-api

# 2) หน้าเว็บ: เสิร์ฟจากเครื่องนี้เท่านั้น
python -m http.server 8080 --bind 127.0.0.1 --directory stack/examples/web
```

เปิด `http://127.0.0.1:8080` ใส่รหัสที่ตั้งใน `APP_API_KEY` แล้วพิมพ์คำถาม

ต้องเสิร์ฟหน้าผ่าน `http://` แบบนี้ เปิดไฟล์ตรงๆ ด้วยการดับเบิลคลิกไม่ได้ เพราะเบราว์เซอร์จะส่งที่มาเป็น `null` ซึ่ง ai-api ไม่ยอมรับ

## สิ่งที่หน้านี้สอน

| เรื่อง | ดูที่ไหนในไฟล์ |
|---|---|
| HTML บอกว่าหน้ามีอะไร: หัวข้อ ช่องกรอก ปุ่ม และป้ายกำกับที่ผูกกับช่อง | ส่วน `<main>` |
| CSS บอกหน้าตา: ตัวแปรสี ธีมสว่างและมืด และการจัดเรียงที่ปรับตามความกว้างจอ | ส่วน `<style>` |
| JavaScript เรียก API: `fetch` แบบ POST พร้อม header `Authorization` | ส่วน `<script>` |
| ข้อผิดพลาดแต่ละแบบบอกผู้ใช้ต่างกัน (รหัสผิด ส่งถี่เกิน ติดต่อไม่ได้) | ตัวแปร `PROBLEMS` |
| คำตอบของโมเดลถูกใส่ด้วย `textContent` จึงไม่ถูกรันเป็น HTML | บรรทัดที่ตั้ง `el('reply').textContent` |

## ข้อจำกัด

- รหัสของบริการเป็นรหัสร่วม ใครมีรหัสก็เรียกได้ หน้านี้จึงเหมาะกับใช้ในเครื่องหรือในทีมที่ไว้ใจกัน ถ้าจะเปิดให้คนทั่วไปใช้ต้องมีระบบบัญชีผู้ใช้ฝั่งเซิร์ฟเวอร์ ซึ่งคู่มือนี้ยังไม่มี
- ยังไม่มีการแสดงคำตอบแบบทยอยขึ้น (ai-api มี `/api/chat/stream` แล้ว แต่หน้านี้ยังไม่ใช้)
- ทดสอบกับ ai-api ที่ต่อกับเซิร์ฟเวอร์จำลองในเบราว์เซอร์หนึ่งตัวบน Windows ยังไม่ได้ทดสอบกับ Claude API จริงและเบราว์เซอร์อื่น
