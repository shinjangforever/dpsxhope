# หุ่นยนต์ (Robotics): จาก AI สู่กลไก

> แผนที่สาขาแรกของ dpsxhope · เวอร์ชัน 0.2 · ตรวจแหล่งอ้างอิงล่าสุด 2026-11-10
> **สถานะการทดสอบ:** ทดสอบแล้วในเครื่อง (จำลอง ไม่มีฮาร์ดแวร์): เดโมใน [`heart-to-mechanism/`](heart-to-mechanism/), เครื่องมือ [`robokit/`](robokit/) และด่านตรวจใน `ros2_llm_bridge.py` ส่วนที่ชี้ไปเครื่องมือภายนอกยังไม่ได้ลองเอง

หุ่นยนต์คือจุดที่ AI ต้องรับผิดชอบกับโลกกายภาพ คำตอบที่ผิดในแชตแก้ได้ด้วยการถามใหม่ แต่คำสั่งที่ผิดกับมอเตอร์แก้ไม่ได้
แผนที่นี้จึงเริ่มจากคำถามเดียว: ความฉลาดเดินทางผ่านอะไรบ้างกว่าจะกลายเป็นการเคลื่อนไหว

เริ่มอ่านที่ [บทที่ 1 จากหัวใจสู่กลไก](01-heart-to-mechanism.md) (12 นาที พร้อมเดโมที่รันได้)
มีหุ่นยนต์หรือโปรเจกต์ของตัวเองแล้ว ไปที่ [นำไปใช้กับหุ่นยนต์ของคุณ](#นำไปใช้กับหุ่นยนต์ของคุณ-robokit)

## แผนที่ในหน้าเดียว: จากหัวใจสู่กลไก

| ชั้น | ทำอะไร | เทคโนโลยีที่พบบ่อย | AI เข้ามาตรงไหน |
|---|---|---|---|
| **หัวใจ** | เข้าใจเป้าหมาย วางแผนระดับสูง | โมเดลภาษา, โมเดลภาพ-ภาษา-การกระทำ (VLA) | ตัดสินใจจากภาษาและภาพ |
| **ประสาทสัมผัส** | อ่านโลกจากกล้อง LiDAR IMU | การมองเห็นด้วยคอมพิวเตอร์, SLAM | โมเดลมองภาพ ตรวจจับวัตถุ |
| **ระบบประสาท** | ส่งข้อความระหว่างส่วนต่างๆ แบบเวลาจริง | ROS 2 | แทบไม่เกี่ยว (เป็นโครงสร้างพื้นฐาน) |
| **ด่านความปลอดภัย** | ปฏิเสธคำสั่งที่เกินขอบเขตก่อนถึงตัวควบคุม | กฎตายตัวในซอฟต์แวร์ | ไม่ควรให้ AI เป็นผู้ตัดสินชั้นนี้ |
| **ชั้นป้องกันของกลไก** | คอยดูตำแหน่ง ความเร็ว และชีพจรของตัวควบคุม ตัดกำลังเมื่อผิดปกติ ไม่ฟังชั้นบน | สวิตช์ตำแหน่งสุดทาง ตัวจำกัดแรงบิด watchdog ปุ่มหยุดฉุกเฉินที่ตัดไฟ มาตรฐาน ISO | ไม่ควรมี AI อยู่ในชั้นนี้ |
| **ตัวควบคุม** | แปลงเป้าหมายเป็นแรงหรือแรงบิดทุกมิลลิวินาที | PID, MPC | งานวิจัยใช้การเรียนรู้เสริม แต่ตัวควบคุมคลาสสิกยังพบทั่วไป |
| **กลไก** | มอเตอร์ เฟือง ข้อต่อ โครงสร้าง | วิศวกรรมเครื่องกลและไฟฟ้า | ใช้ AI ช่วยออกแบบได้ แต่ฟิสิกส์ไม่ต่อรอง |

หลักคิดสี่ข้อที่เดโมในบทที่ 1 พิสูจน์ได้ในแบบจำลองนี้: ผลลัพธ์ของ AI คือข้อเสนอที่ชั้นล่างมีสิทธิ์ปฏิเสธ ยิ่งแรงไม่ได้ยิ่งดี ตัวควบคุมต้องรู้ขีดจำกัดของมอเตอร์ และต้องออกแบบโดยสมมติว่าทุกชั้นพังได้ จึงมีชั้นป้องกันของกลไกที่ไม่เชื่อใครเฝ้าอีกชั้น

## เส้นทางเรียน 5 ขั้น (simulator ก่อนฮาร์ดแวร์เสมอ)

สัญลักษณ์: ✅ ทำและทดสอบแล้วในโปรเจกต์นี้ · ⬜ ชี้ไปเครื่องมือภายนอก ยังไม่ได้ลอง

| ขั้น | ทำอะไร | ผ่านเมื่อ | สถานะ |
|---|---|---|---|
| 1. ตัวควบคุม | รัน [`simulate.py`](heart-to-mechanism/simulate.py) ปรับ kp ki kd | จูนให้เกินเป้าไม่เกิน 5% และนิ่งภายใน 2 วินาที อธิบายได้ว่า windup คืออะไร | ✅ |
| 2. ด่านและชั้นป้องกัน | เพิ่มกฎใน `gate()` และลองถอดด่านด้วย `--bypass-gate` ดูว่า `guard` ยังกันได้ไหม แล้วเขียนไฟล์กฎของเครื่องตัวเองด้วย `robot gate` และตรวจระยะหยุดด้วย `robot stop` | มีข้อทดสอบที่พิสูจน์ว่าคำสั่งที่ไม่ปลอดภัยถูกปฏิเสธ และเมื่อด่านพังชั้นป้องกันยังหยุดก่อนชนปลายราง | ✅ |
| 3. จำลองหุ่นยนต์จริง | ติดตั้ง [MuJoCo](https://mujoco.org) หรือ [Gazebo](https://gazebosim.org) ทำแขนกล 2 ข้อต่อให้ถึงเป้า | ควบคุมแขนได้โดยค่าความคลาดเคลื่อนนิ่งต่ำกว่าที่ตั้ง | ⬜ |
| 4. ระบบประสาท | เรียนพื้นฐาน [ROS 2](https://docs.ros.org/en/jazzy/Releases.html) แล้วดู [`ros2_llm_bridge.py`](../../domains/robotics/ros2_llm_bridge.py) (มีด่านตรวจของ robokit แล้ว รัน `--offline` ได้) | เขียน node ที่ส่งข้อความได้ และให้ทุกคำสั่งผ่าน `Gate` ก่อน publish | ⬜ (ด่านตรวจทดสอบแล้ว ส่วน ROS 2 ยังไม่ได้ลอง) |
| 5. ฮาร์ดแวร์จริง | เมื่อพร้อมแล้วเท่านั้น | มีปุ่มหยุดฉุกเฉินที่ไม่พึ่งซอฟต์แวร์ ประเมินความเสี่ยงแล้ว มีผู้ที่มีประสบการณ์กำกับ | ⬜ |

## ความปลอดภัยและจริยธรรม

สาขานี้ต่างจากสาขาอื่นที่ความผิดพลาดทำให้คนบาดเจ็บได้ จึงมีข้อกำหนดหนักกว่า

1. **simulator ก่อนเสมอ** ไม่ต่อโค้ดจากโปรเจกต์นี้เข้ากับฮาร์ดแวร์ที่เคลื่อนที่ได้ ถ้ายังไม่มีผู้เชี่ยวชาญและมาตรการด้านล่าง
2. **ปุ่มหยุดฉุกเฉินต้องเป็นอิสระจากซอฟต์แวร์** (ตัดพลังงานที่ฮาร์ดแวร์) ซอฟต์แวร์หยุดไม่ได้ถ้าซอฟต์แวร์ค้าง และควรมีชั้นป้องกันของกลไกแยกต่างหาก (เดโมในบทที่ 1 แสดงว่าตัวควบคุมค้างหรือหัวใจเพ้อแล้วชั้นนี้ยังหยุดทันก่อนชนปลายราง ในแบบจำลองนี้)
3. **อย่าให้ AI เป็นด่านสุดท้าย** ใช้กฎตายตัวตรวจคำสั่ง ปฏิเสธมากกว่าปรับค่าให้เงียบๆ และอย่าใช้ค่า "ความมั่นใจ" ที่โมเดลรายงานเองเป็นตัวกัน
4. **ผู้เขียนรายงานว่า LLM ที่ควบคุมหุ่นยนต์ถูกหลอกให้ทำสิ่งอันตรายได้** ดู Robey และคณะ [Jailbreaking LLM-Controlled Robots](https://arxiv.org/abs/2410.13691) (2024) บนระบบที่ทดสอบ 3 แบบ
5. **มาตรฐาน** ISO 10218-1:2025 (ผู้ผลิตหุ่นยนต์อุตสาหกรรม) และ ISO 10218-2:2025 (ผู้ผสานระบบและเซลล์หุ่นยนต์) ออกเมื่อ 2025-02 แทนฉบับปี 2011
   ตามรายงานของ A3 ฉบับใหม่รวมข้อกำหนดของหุ่นยนต์ร่วมงานกับคนที่เคยอยู่ใน ISO/TS 15066 แต่หน้าของ ISO ยังกล่าวถึง TS 15066 แยกต่างหาก
   สองแหล่งไม่ตรงกัน ให้ตรวจกับ ISO โดยตรงก่อนอ้างอิงในงานจริง ([ISO 10218-2](https://www.iso.org/standard/73934.html), [A3 FAQ](https://www.automate.org/robotics/blogs/updated-iso-10218-faq))
   สองหน้านี้เปิดอัตโนมัติไม่ได้ในการตรวจรอบนี้ (เซิร์ฟเวอร์ปฏิเสธ) ผมอ่านผ่านผลค้นหา ให้เปิดผ่านเบราว์เซอร์
6. **เนื้อหานี้ไม่ใช่คำแนะนำด้านวิศวกรรมความปลอดภัยหรือกฎหมาย**

## นำไปใช้กับหุ่นยนต์ของคุณ (robokit)

[`robokit/`](robokit/) เปลี่ยนหลักคิดในบทที่ 1 ให้เป็นเครื่องมือที่ใส่ค่าของเครื่องตัวเองได้ ใช้ Python มาตรฐานล้วน รันผ่าน `python hope.py robot ...`

| คุณอยู่ตรงไหน | เริ่มที่คำสั่ง | ได้อะไร |
|---|---|---|
| มีแค่ไอเดีย | `robot plan` | แผนเป็นขั้นที่มีเกณฑ์ผ่าน + ไฟล์กฎตั้งต้น เรียงตามชั้นในแผนที่ |
| กำลังต่อ AI เข้ากับหุ่นยนต์ | `robot gate` | ด่านตรวจคำสั่งจากไฟล์กฎ: ช่วงค่า เขตห้ามเข้า ระยะต่อครั้ง ความถี่ audit log |
| มีมอเตอร์และกลไกแล้ว | `robot tune` | ค่า PID เริ่มต้นที่ทดสอบแล้วว่าทนต่อมวลและแรงเสียดทานที่วัดคลาด ±30 % |
| กำลังออกแบบชั้นป้องกัน | `robot stop` | ระยะหยุดจริง ระยะเผื่อ และความเร็วสูงสุดที่ยังหยุดทัน |

ตัวอย่างการต่อกับ LLM จริง: [`domains/robotics/ros2_llm_bridge.py`](../../domains/robotics/ros2_llm_bridge.py) ส่งคำตอบของโมเดลเข้า `Gate` ก่อนทุกครั้ง
ค่า `confidence` ของโมเดลใช้แค่ตัดสินว่าควรถามผู้ใช้ซ้ำไหม ไม่ใช่ตัวกันความปลอดภัย
รัน `python domains/robotics/ros2_llm_bridge.py --offline` จะเห็นด่านปฏิเสธคำสั่งไป 30 เมตร คำสั่งที่พยายามปิดกฎ และส่งคำสั่งกำกวมกลับไปถาม

### เช็กลิสต์ก่อนต่อฮาร์ดแวร์

- [ ] ไฟล์กฎผ่าน `robot gate validate` และชุดคำสั่งทดสอบ (รวมคำสั่งอันตรายและคำสั่งชวนหลง) ถูกปฏิเสธครบ
- [ ] ทุกเส้นทางที่ส่งคำสั่งถึงตัวควบคุม (AI, ปุ่ม, สคริปต์, เครือข่าย) ผ่าน `Gate` เดียวกัน
- [ ] ค่า PID ผ่าน `robot tune` ด้วยค่ามวลและแรงเสียดทานที่วัดจริง และเริ่มจาก 50 % บนฮาร์ดแวร์
- [ ] วัดระยะหยุดจริงแล้วใส่ใน `robot stop` ยังผ่านที่ความเร็วสูงสุดที่ตั้งไว้
- [ ] ชั้นป้องกันของกลไกแยกจากคอมพิวเตอร์ที่รัน AI และตัวควบคุม ปุ่มหยุดฉุกเฉินตัดไฟที่ฮาร์ดแวร์
- [ ] ถ้าทำงานใกล้คนหรือในโรงงาน ผ่านการประเมินความเสี่ยงโดยผู้มีประสบการณ์ตามมาตรฐาน

## ที่ยังไม่ครอบคลุม (ตามจริง)

- การมองเห็นและ SLAM ในเชิงลึก, จลนศาสตร์ของแขนกล, การออกแบบกลไก, หุ่นยนต์เดินสองขา, โดรน
- เดโมที่ใช้ LLM หรือ VLA จริงแทน "หัวใจ" ในบทที่ 1 (ตอนนี้ใช้กฎเพื่อให้ผลซ้ำได้ ส่วน `ros2_llm_bridge.py` เรียก Claude ได้แต่ยังไม่ได้ทดสอบกับ API จริง)
- `robokit` กับหุ่นยนต์จริง ROS 2 จริง และแกนที่มีแรงโน้มถ่วงหรือแรงเสียดทานคูลอมบ์
- การทดสอบบน macOS และ Linux (เดโมเป็น Python มาตรฐาน คาดว่ารันได้ แต่ยังไม่ได้ลอง)

## สะพานไปสาขาอื่น (ยังเป็นไอเดีย ยังไม่มีเนื้อหา)

- **anatomy:** กล้ามเนื้อและข้อต่อเป็นแรงบันดาลใจของตัวขับเคลื่อนและโครงสร้าง
- **3D:** ออกแบบและพิมพ์ชิ้นส่วนก่อนมีฮาร์ดแวร์
- **games:** เอนจินฟิสิกส์ของเกมกับ simulator ของหุ่นยนต์ใช้หลักการร่วมกัน
