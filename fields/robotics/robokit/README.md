# robokit: เครื่องมือหุ่นยนต์ที่ใช้กับเครื่องของคุณ

> ส่วนหนึ่งของ[แผนที่สาขาหุ่นยนต์](../README.md) · Python มาตรฐานล้วน ไม่ต้องติดตั้งอะไรเพิ่ม · ทดสอบ 32 ข้อใน `tests/test_robokit.py`

บทที่ 1 แสดงหลักคิดด้วยเดโม ส่วน robokit นำหลักคิดเดียวกันไปใช้กับหุ่นยนต์ของคุณ โดยแก้แค่ไฟล์กฎและใส่ค่าของเครื่อง

| คำสั่ง | ตอบคำถาม | ได้อะไร |
|---|---|---|
| `robot plan` | ควรเริ่มตรงไหน ต้องผ่านอะไรก่อนต่อฮาร์ดแวร์ | `plan.md` แยกเป็นขั้นที่มีเกณฑ์ผ่าน + `safety-profile.json` ตั้งต้น |
| `robot gate` | คำสั่งจาก AI นี้ปลอดภัยพอจะส่งต่อไหม | ผ่าน/ปฏิเสธพร้อมเหตุผล, audit log, ใช้เป็นไลบรารีใน Python ได้ |
| `robot tune` | ตั้ง PID เท่าไรดี และทนต่อค่าที่วัดคลาดไหม | kp, kd พร้อมตารางผลในกรณีเลวร้าย และกราฟ SVG |
| `robot stop` | ชั้นป้องกันหยุดทันก่อนชนไหม ต้องจำกัดความเร็วเท่าไร | ระยะหยุด ระยะเผื่อ ความเร็วสูงสุดที่ปลอดภัย |

ทุกคำสั่งเรียกผ่าน `python hope.py robot ...` ที่ root ของ repo (หรือ `cd fields/robotics` แล้ว `python -m robokit ...`)
exit code: `0` ผ่าน · `1` ใช้คำสั่งหรือไฟล์ผิด · `2` มีคำสั่งถูกปฏิเสธหรือไม่ผ่านเกณฑ์ (ใช้ใน CI หรือสคริปต์ได้)

## เริ่มใน 3 นาที

```bash
python hope.py robot plan
```

ตอบ 5 ข้อ (แบบหุ่นยนต์ ขั้นที่อยู่ ใช้ AI ไหม ใกล้คนไหม ใช้ทำอะไร) แล้วจะได้โฟลเดอร์ `my-robot/` ที่มีแผนและไฟล์กฎ

## ด่านตรวจคำสั่ง (gate)

ไฟล์กฎเป็น JSON บอกว่า action ไหนทำได้ แต่ละพารามิเตอร์มีชนิดและช่วงอะไร ดูตัวอย่างใน [`profiles/`](profiles/)

```bash
python hope.py robot gate examples                                   # ดูตัวอย่างที่มี
python hope.py robot gate init my-arm.json --example desk-arm-2axis  # สร้างจากตัวอย่าง แล้วแก้ตัวเลข
python hope.py robot gate validate my-arm.json                       # ตรวจไฟล์กฎ
python hope.py robot gate check my-arm.json fields/robotics/robokit/examples/desk-arm-commands.jsonl --state '{"x": 0, "y": 0.3}' --log audit.jsonl
```

ใช้ในโค้ดของคุณ:

```python
import sys; sys.path.insert(0, "fields/robotics")
from robokit import Gate

gate = Gate.from_file("my-arm.json", log_path="audit.jsonl")
decision = gate.check(llm_json, state={"x": 0.0, "y": 0.3})   # state = ค่าที่วัดได้จริง
if decision:
    send_to_controller(decision.command)
else:
    print(decision.reasons)
```

ตัวอย่างที่ต่อกับ LLM จริงอยู่ใน [`domains/robotics/ros2_llm_bridge.py`](../../../domains/robotics/ros2_llm_bridge.py)
(รัน `--offline` ได้โดยไม่ต้องมี key จะเห็นด่านปฏิเสธคำสั่ง 30 เมตร และคำสั่ง "ignore your rules")

| หัวข้อในไฟล์กฎ | ความหมาย |
|---|---|
| `actions.<ชื่อ>.params` | พารามิเตอร์แต่ละตัว: `number`/`integer` (ต้องมี `min` `max`), `enum` (`values`), `string` (`max_length`), `boolean` ใส่ `unit` และ `default` ได้ |
| `actions.<ชื่อ>.required` | พารามิเตอร์ที่ต้องใส่ |
| `actions.<ชื่อ>.max_step` | เปลี่ยนได้ไม่เกินเท่าไรต่อคำสั่ง เทียบกับ `state` ที่วัดได้จริง (ไม่มี state = ปฏิเสธ) |
| `keep_out` | เขตห้ามเข้า เช่น `{"name": "ฐานแขน", "x": [-0.08, 0.08], "y": [0.1, 0.16]}` |
| `ignore_fields` | ฟิลด์ที่ยอมให้มีแต่ไม่ใช้ เช่น `confidence` ของ LLM |
| `always_allow` | action ที่ไม่ติด rate limit (ควรมี `stop`) |
| `rate_limit_per_s` | จำนวนคำสั่งที่ผ่านได้ต่อวินาที |

หลักที่ด่านยึด: ปฏิเสธแทนการปรับค่าเงียบๆ · ฟิลด์หรือ action ที่ไม่รู้จัก = ปฏิเสธทั้งคำสั่ง · ไม่เชื่อค่าความมั่นใจของโมเดล ·
ไม่รู้ข้อมูลที่ต้องใช้ตรวจ = ปฏิเสธ · ไฟล์กฎที่ตั้งผิด (เช่น ตัวเลขไม่มีขอบเขต) โหลดไม่ขึ้นตั้งแต่ต้น

## หาค่า PID (tune)

```bash
python hope.py robot tune --mass 1.0 --friction 0.8 --max-force 20 --step 0.2 --travel 1.0 --svg tune.svg
```

ผลจริงกับค่าด้านบน (เครื่องเดียวกับเดโมบทที่ 1): kp ≈ 278, kd ≈ 39 เกินเป้าสูงสุด 2.75 % และนิ่งภายใน 0.61 s
ในทั้ง 6 กรณี (ค่าที่วัดได้ และมวล/แรงเสียดทานคลาด ±30 %, ระยะ 0.2 และ 1.0) ในแบบจำลองนี้

ใช้กับแกนหมุนได้: มวล → โมเมนต์ความเฉื่อย (kg·m²), แรงเสียดทาน → ความหน่วง (N·m·s/rad), แรง → แรงบิด (N·m), ระยะ → มุม (rad)

## ระยะหยุด (stop)

```bash
python hope.py robot stop --speed 0.5 --react 0.05 --decel 5 --available 0.1
```

ระยะหยุด = ความเร็ว × เวลาตอบสนอง + ความเร็ว² ÷ (2 × อัตราหน่วง) ต้องคูณตัวเผื่อ (ค่าเริ่มต้น 1.5) แล้วยังไม่เกินระยะที่มี
ถ้าไม่ผ่าน จะบอกความเร็วสูงสุดที่ยังหยุดทันและอัตราหน่วงที่ต้องมี

## ข้อจำกัด (ตามจริง)

- ทดสอบแล้วเฉพาะในเครื่อง กับแบบจำลองและคำสั่งตัวอย่าง ยังไม่เคยต่อกับหุ่นยนต์จริงหรือ ROS 2 จริง
- `tune` ใช้แบบจำลองเดียวกับบทที่ 1 (ไม่มีแรงโน้มถ่วง แรงเสียดทานคูลอมบ์ ช่องฟรีของเฟือง หรือสัญญาณรบกวน) ค่าที่ได้คือจุดเริ่มจูน
- `stop` สมมติอัตราหน่วงคงที่ ค่าที่ใส่ต้องมาจากการวัดหยุดจริง ตัวเผื่อ 1.5 เป็นค่าตั้งต้นของเครื่องมือนี้ ไม่ใช่ค่าจากมาตรฐาน
- ด่านตรวจเป็นซอฟต์แวร์ ไม่รู้ว่ามีคนอยู่ตรงเป้าหมาย หุ่นยนต์จริงต้องมีชั้นป้องกันที่เป็นฮาร์ดแวร์และปุ่มหยุดฉุกเฉินที่ตัดไฟ
- ไม่ใช่คำแนะนำด้านวิศวกรรมความปลอดภัยหรือกฎหมาย งานใกล้คนหรือในโรงงานต้องประเมินความเสี่ยงตามมาตรฐานโดยผู้มีประสบการณ์
