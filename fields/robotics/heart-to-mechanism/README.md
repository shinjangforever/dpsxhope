# เดโม: จากหัวใจสู่กลไก

หุ่นยนต์แกนเดียวที่จำลองสายส่งครบหกชั้น: คำสั่ง > ด่านความปลอดภัย > ตัวควบคุม PID > มอเตอร์ > กลไก โดยมีชั้นป้องกันของกลไกเฝ้าอยู่ข้างๆ
ใช้ Python มาตรฐานอย่างเดียว ไม่ต้องติดตั้งอะไรเพิ่ม ไม่ต้องมี API key และไม่ต้องมีฮาร์ดแวร์

อ่านคู่กับ [บทที่ 1](../01-heart-to-mechanism.md)

## รัน

```bash
python fields/robotics/heart-to-mechanism/simulate.py "ไปที่ 1 เมตร"
python fields/robotics/heart-to-mechanism/simulate.py --compare --svg compare.svg
```

| คำสั่งที่เข้าใจ | ความหมาย |
|---|---|
| `ไปที่ 1.5 เมตร`, `move to 1.5`, `go to -0.5` | ไปยังตำแหน่งนั้น (เมตร) |
| `เดินหน้า 2 เมตร`, `forward 2` | ไปข้างหน้าจากตำแหน่งเริ่มต้น |
| `ถอยหลัง 1 เมตร`, `back 1` | ถอยหลัง |
| `หยุด`, `stop` | หยุด (ชนะทุกคำสั่งในประโยคเดียวกัน) |

คำสั่งที่ไม่เข้าใจหรือไม่ปลอดภัยจบด้วย exit code 2 และข้อความ "ปฏิเสธ" ไม่เดาแทนผู้ใช้ ส่วนการจำลองที่จบด้วยการชนปลายรางคืน exit code 3

## ค่าที่ปรับได้

| ตัวเลือก | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `--kp`, `--ki`, `--kd` | 40, 2, 12 | ค่าของตัวควบคุม PID |
| `--max-force` | 20 | แรงสูงสุดที่มอเตอร์ให้ได้ (นิวตัน) |
| `--no-anti-windup` | เปิด anti-windup | ปิดการหยุดสะสมอินทิกรัลเมื่อมอเตอร์อิ่มตัว |
| `--workspace` | 2 | พื้นที่ที่ด่านความปลอดภัยอนุญาต ± เมตร |
| `--compare` | ปิด | เทียบห้าสถานการณ์ของตัวควบคุมในกราฟเดียว |
| `--faults` | ปิด | จำลองหัวใจเพ้อและตัวควบคุมค้าง เทียบตอนมีและไม่มีชั้นป้องกัน (ใช้คู่กับ `--svg`) |
| `--bypass-gate` | ปิด | ทดลอง: จำลองว่าด่านซอฟต์แวร์พัง ห้ามใช้กับของจริง |
| `--no-guard` | เปิดชั้นป้องกัน | ทดลอง: ปิดชั้นป้องกันของกลไกเพื่อดูว่าไม่มีแล้วเป็นอย่างไร |
| `--freeze-at วินาที` | ไม่ค้าง | ทดลอง: ตัวควบคุมค้างที่คำสั่งสุดท้ายและหยุดส่งชีพจร |
| `--svg ไฟล์.svg` | ไม่เขียน | เขียนกราฟตำแหน่งตามเวลา |

ค่ามวล (1 kg) แรงเสียดทาน (0.8 N·s/m) หน่วงมอเตอร์ (20 ms) และขีดของชั้นป้องกัน (ตำแหน่ง 2.25 m, ความเร็ว 8 m/s, watchdog 100 ms, ปลายราง 2.5 m) อยู่ใน `Params` ในไฟล์ `simulate.py` แก้ได้โดยตรง
ขีดของชั้นป้องกันตั้งให้เข้ากับแบบจำลองนี้ เช่น งานปกติ 2 เมตรมีความเร็วสูงสุดราว 4.4 m/s ถ้าตั้งขีดความเร็วต่ำกว่านั้นจะตัดงานปกติ

## เอาไปปรับใช้

- **ต่อ AI จริง:** เปลี่ยนฟังก์ชัน `decide()` ให้เรียก LLM แล้วคืน dict รูปแบบเดียวกัน (`{"action": ..., "target_m": ...}`) ส่วน `gate()` และที่เหลือไม่ต้องแก้ ห้ามข้าม `gate()` ไม่ว่าโมเดลจะมั่นใจแค่ไหน
- **เพิ่ม action:** เพิ่มชื่อใน `ALLOWED_ACTIONS` และกฎตรวจใน `gate()` ก่อน แล้วค่อยเพิ่มพฤติกรรม
- **เปลี่ยนหุ่นยนต์:** แก้ `simulate()` ให้ตรงกับฟิสิกส์ของจริง (วัดพารามิเตอร์จากเครื่องก่อน) ตัวชี้วัดใน `_metrics()` ใช้ต่อได้

## ทดสอบ

```bash
python -m unittest discover -s tests -p test_robotics_demo.py
```

ชุดทดสอบตรวจสิ่งที่บทเรียนอ้าง: ด่านความปลอดภัยปฏิเสธคำสั่งที่ไม่ปลอดภัย ตัวควบคุมที่จูนแล้วนิ่ง ตัวที่จูนผิดแกว่ง มอเตอร์ไม่เกินขีดจำกัดแรง anti-windup ลดการเกินเป้า งานปกติไม่ถูกชั้นป้องกันตัด และเมื่อด่านพังหรือตัวควบคุมค้างชั้นป้องกันหยุดก่อนชนปลายราง

## ข้อจำกัด

แบบจำลองของเล่น (มวลเดียว แรงเสียดทานเชิงเส้น ไม่มีสัญญาณรบกวน ไม่มีความหน่วงของการสื่อสาร) ตัวเลขใช้ได้กับแบบจำลองนี้เท่านั้น
ไม่ใช่ระบบความปลอดภัยที่ผ่านมาตรฐาน และไม่ควรใช้ควบคุมฮาร์ดแวร์จริง ชั้นป้องกันในเดโมอยู่ในโปรแกรมเดียวกับส่วนอื่น จึงยังไม่อิสระจริง ของจริงต้องแยกเป็นฮาร์ดแวร์หรือโปรเซสแยก
